# 62 · 权重布局探针：抓到了结构特征，但 one-hot 不够 —— 改用「斜坡探针」

> 接 [docs/61](61-全仿真的地基-抓到NPU看到的真实DRAM镜像.md)（DRAM 镜像抓取）。
> 本轮用**已知明文**攻权重布局：造一个权重是 one-hot 的探针模型，转换后看非零字节落在哪。
> **拿到了两个很干净的结构签名，但也发现 one-hot 这个设计不足以读出布局** —— 下轮改用斜坡探针。

---

## 0. 本轮拿到的（都是新事实）

### 探针模型（`deploy/probe_weight_layout.py --make`）

```
输入 1×3×32×32
conv1: 3→16, k=3, s=1, p=1   ← one-hot 权重：每个 oc 只有一个 1.0，位置互不相同
conv2: 16→8,  k=1            ← 权重全 1.0
fc:    8→4
```

### 抓到的缓冲区（板上实测）

| 设备地址 | 大小 | 判读 |
|---|---|---|
| `0xfffe4000` / `0xfffe5000` / `0xfffff000` | 4,096 ×3 | 参数/控制块 |
| **`0xfffe6000`** | **69,632** | ★ **只有两个取值：`0` 与 `128`** |
| **`0xffff7000`** | **32,768** | ★ 205 种取值（像真实量化数据） |

### 结构签名一：`0xfffe6000` 只有 {0, 128} 两个值

```
非零（=128）占比 35.58%
前 40 个非零位置: [0..7, 16..23, 32..39, 48..55, 64..71, ...]
相邻非零间距分布: {1: 23726, 9: 1047, 2681: 1, 16385: 1}
取值种类: 2     最常见: (0, 44856), (128, 24776)
```

**⇒ 明显的「8 个连续非零 / 跳过 8 个」周期 16 的块状结构**（间距 1 出现在块内，9 出现在块间）。

### 结构签名二：`0xffff7000` 有 205 种取值

```
非零占比 53.50%
取值种类 205；最常见: (0,15237), (1,3127), (2,1038), (3,129), (4,136), (5,22), (6,117), ...
```

---

## 1. ★ 一个关键发现：**权重用的 zero_point 不是 0**

探针的 conv1 权重**绝大部分是 0.0**（16×3×3×3 里只有 16 个 1.0）。
如果量化把 `0.0 → 0`，那这个缓冲区应该**绝大部分是 0**；但实测非零占 35.6%，
而且**取值只有 0 和 128**。

**⇒ 合理的解释：`128`（有符号 INT8 的 −128）是权重张量的 zero_point，
即浮点 `0.0` 映射到字节 `128`。** 这解释了「本该几乎全 0 的权重缓冲区里有大量 128」。

**这个结论对执行器很关键**：反量化必须是
`w_float = (w_int8 − zero_point) × scale`，**不能假设 zero_point = 0**。

（⚠️ 这是**推断**，还没有独立验证 —— 下轮的斜坡探针会顺带验证它：
如果 0.0 真的映射到 128，那么斜坡里最小的浮点值应当映射到 128 附近。）

---

## 2. 为什么 one-hot 不够（本轮的方法论收获）

one-hot 只回答「**非零在哪**」，不回答「**顺序是什么**」。
它给出了一个周期 16 的块结构，但我**无法从它推出**：

* 哪个维度对应块内/块间？
* `oc` 与 `ic` 的先后？
* 通道对齐到 16 还是 32？

而且**padding 区域也写成 zero_point（128）而不是 0** ⇒
「非零位置」里混着**真实权重**与**对齐填充**，两者分不开。

### ⇒ 下一轮改用**斜坡探针（ramp probe）**

```
让权重值 = 它在逻辑张量里的线性序号（乘一个系数落在量化范围内）
⇒ 量化后的字节**随序号单调变化**
⇒ 按字节值排序，就**直接读出排列顺序**（哪个逻辑位置落在哪个物理偏移）
```

**斜坡比 one-hot 强的地方**：
* 它同时编码了「位置」与「顺序」；
* padding 会用同一个值 ⇒ 与斜坡值可区分；
* 只要量化范围选得合适（不截断），映射是**可逆的**。

## 4. 教训（本轮新增）

1. **★ 探针设计要同时编码「位置」和「顺序」。** one-hot 只给位置，
   于是我拿到了一个周期 16 的块结构却推不出维度 —— **等于做了半个实验**。
   下一版用斜坡，一次拿到顺序。
2. **★ padding 会污染「非零」这个判据。** 我以为「非零 = 真实权重」，
   但 zero_point=128 让**对齐填充也非零** ⇒ 判据失效。
   **设计探针前要先想「什么会被填充成什么」。**
3. **★ 顺手拿到的结论也要记。** `zero_point ≠ 0` 不是本轮的目标，
   但它对执行器的反量化是**必需**的，而且是从「本该全 0 却 35% 非零」这个矛盾里推出来的。
   **矛盾的地方往往藏着真结论。**
4. **★ 半个实验也要落盘。** 本轮的块结构签名（周期 16、8/8 分块）**本身是有用的线索**，
   下一轮做斜坡探针时可以直接对照。**不完整的观测不等于没有价值。**
