## 1. ★★ 入口一：`rknn.api.fuse_rules.hardware_rules` —— **12 条 tiling 规则表**

```python
from rknn.api import fuse_rules as F
F.hardware_rules        # dict，12 条
```

```
keys:
  convert_conv_to_pad_conv      tiling_maxpool            tiling_global_maxpool
  tiling_depthwise_conv    ★    tiling_group_conv_act  ★  tiling_conv_channelin   ★
  tiling_deconv_channelin       convert_reducesum_to_einsum
  convert_exmatmul_to_conv      p_tiling_exmatmul_channel
  gather_to_conv                fix_exsoftmax_axis

每条形如：
  {'ops': ['Conv'], 'proc': <cyfunction _p_tiling_depthwise_conv at 0x…>}
```

**⇒ 这是编译器**真实的、按算子分派的 tiling 规则**，而且 `proc` 是**可调用的**。**

### 为什么这直接命中未解问题

* 未解问题：「**什么驱动提交切分**」—— 我否掉了 6 条假设，一直没找到
* **tiling 规则决定 tile 怎么切；tile 结构决定提交怎么打包** ⇒ **规则表就是答案的所在**
* 而且它**解释了 docs/93 的失败**：`tiling_depthwise_conv` 是**独立的一条规则** ⇒
  **depthwise 确实被特殊对待**，但**特殊之处在 tiling，不在提交切分** ——
  所以我那个「depthwise vs 部分分组」的探针测错了对象

**⇒ 下一步：直接读/调用这些 `proc`，看它们对给定 shape 产出什么 tiling。**

## 2. ★★ 入口二：`rknn.api.ir_graph` —— IR 里有 **`layout` 属性**

`rknn_base.so` 的字符串里有：

```
layout          layout_ori          weight_mem          weight_memory          weights_quant
```

**⇒ 布局在 IR 里是**显式记录的属性**，不需要从字节反推！**

`rknn.api.ir_graph` 暴露：

```
IRGraph, Operand, ACTIVATION_OPS, ELEMENTWISE_ALU_OPS, REDUCE_OPS,
inf_shape, update_model_value_info, …
```

**⇒ 用 `IRGraph` 加载一个模型，读每个 tensor 的 `layout` / `layout_ori`，
就得到**权威的布局**（而不是我盲探 6 轮的那个）。**
