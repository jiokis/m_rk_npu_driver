|---|---|---|---|---|

## 1. ★ 上轮那个「否证」被推翻了 —— 而且原因很值得记

上轮我这样否掉分组卷积假设：

```
跨 9 个真实模型做相关：「提交数 ~ 分组卷积占比」⇒ R² = 0.016
反例：mnasnet0_5 / mobilenet_v2 各有 17 个 depthwise，只有 3 次提交
```

**本轮受控 A/B 显示分组卷积确实是驱动（7→13）。**
⇒ **上轮的否证是错的。**

**错在哪**：跨模型相关性里有**大量混杂因素**（模型深度、宽度、特征图尺寸、
其它结构差异）。`mnasnet0_5`/`mobilenet_v2` 之所以只有 3 次提交，
不是因为「depthwise 不断提交」，而是因为它们**整体可融合**（无 SE、无分组、
无 Concat，只有 Relu/Clip）—— 分组卷积的效应被整体融合效应**淹没**了。

**⇒ 教训：跨模型相关性可以用来「发现线索」，但不能用来「否证机制」。**
一个 R²≈0 的跨模型相关，**不足以排除**一个真实的因果 —— 必须用受控实验。
（上轮我用 R²=0.016 写下了「否掉」，这是**方法上的过度声称**。）

| `densenet121` | 183 | Concat×62 | ⚠️ **最该重测**（提交数最大） |

### 量级核对：regnet

```
ab_nogroup：6 个 group=1 conv + 1 首层 = 7 个 conv → 7 次提交（≈1 提交/conv）
ab_group  ：6 个 group=8 conv + 1 首层 → 13 次提交（分组那 6 个各多贡献 ~1 次）

regnet_x_400mf：71 个 conv，其中 22 个分组
  粗估 49（group=1）+ 22×2 = 93 次，实测 113 次 —— **同一量级**（差 21%）
```

⇒ **分组卷积能解释 regnet 的大部分提交数**，虽然不是全部。

## 4. 教训（本轮新增）

1. **★ 跨模型相关性不能用来否证机制。** 上轮我用 R²=0.016 写下「否掉分组卷积」，
   本轮受控实验直接推翻。**混杂因素会把真实效应淹没**，R²≈0 只说明「在这批模型上线性不可见」，
   不说明「没有因果」。**这是我在这个目标里第二次犯「判据强度不够却下了强结论」** ——
   上一次是 docs/36 拿错参照物、docs/47 §8 拿读地址当必要条件。
   **共同的根因：把「我没观察到」当成了「不存在」。**
2. **★ 同一个方法用两次，第二次要更警惕。** 否掉布局算子和否掉分组卷积用的是同一套
   （跨模型相关性），第一次「成功」让我第二次更放心 —— 结果第二次错得一样。
   **方法的可信度不因为它用过一次而提高。**
3. **★ 受控实验的代价很低，收益很高。** 造一对模型 + 转换 + 上板测 = 十几分钟，
   但能给出因果。**在有「能自造输入」的能力时，优先做受控而不是观察。**
4. **量级核对比显著性更重要。** 分组卷积对 regnet 的粗估（93）与实测（113）
   差 21%，但**同一个量级**就够了 —— 它说明这是主要因素。
   **要求精确吻合会让我错过正确的解释。**
