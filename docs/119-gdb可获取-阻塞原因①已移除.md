## 1. ★ 结果：gdb 装好了，无需 root

```bash
apt-get download gdb libbabeltrace1 libdebuginfod1t64 libipt2 libsource-highlight4t64
for d in *.deb; do dpkg-deb -x "$d" root/; done
LD_LIBRARY_PATH=.../root/usr/lib/x86_64-linux-gnu .../root/usr/bin/gdb --version
```

```
GNU gdb (Ubuntu 15.1-1ubuntu1~24.04.1) 15.1
```

**⇒ 已沉淀为 `tools/get-gdb.sh`（可重复执行）。**

### 踩到的细节

* 下载 5 个 deb（gdb 本体 4.0 MB + 4 个运行库）
* gdb 本体**缺 4 个库**：`libbabeltrace(-ctf).so.1` / `libdebuginfod.so.1` / `libipt.so.2` / `libsource-highlight.so.4`
* `apt-file` 不可用 ⇒ 包名靠试（`libbabeltrace1` / `libdebuginfod1t64` / `libipt2` / `libsource-highlight4t64`）

**⇒ 阻塞原因从**两个**降为**一个**（只剩「符号表剥离」）。**

**⇒ 而且「符号表剥离」也不是绝对的** —— 有 gdb 之后可以：
* 在 **Python 规则 proc 触发时**下断点，然后 `bt` **看 C++ 调用栈** ⇒ 拿到 pass 函数的地址
* 用那个地址在 `.rodata` 里对照 RTTI（`N4rknn14RKNNTilingPassE` 在 `0x1a8d760`）
* 再沿调用栈向**更晚的 pass** 定位（找 step 20 之后的函数）

**⇒ 这条路比 docs/118 判断的「要先解决两个前置问题再深层反汇编」短得多。**

## 4. 教训（本轮新增）

1. **★★★ 不要接受自己上一轮给出的「不可行」判断 —— 先去验证它的**前置条件**能不能满足。**
   docs/118 我列了「没装 gdb」作为阻塞原因，**却没有先试一下能不能装**。
   本轮一试就装上了（无需 root）。**「环境缺 X」和「X 不可得」是两回事。**
2. **★★ 阻塞原因要按「是否根本性」排序，而不是并列。**
   「没装 gdb」是**可移除**的；「符号表剥离」是**根本性**的。
   **我上一轮把两个并列成「两个前置问题」，夸大了难度。**
3. **★ 装工具本身就是逆向工作的一部分，而且往往比反汇编便宜。**
   5 个 deb、几分钟 ⇒ 把「不可行」变成「有路径」。
