# 141 · ★★★★★ SD 架构在 NPU 上跑通 —— 以及一个**藏得很深**的 NHWC 布局坑

> 接 [docs/140](140-SD架构-预算算术与16配置实测扫描-找到极限甜点.md)（预算与甜点扫描）。
> 本轮把 **VAE 潜空间扩散** 端到端跑上 NPU，并在过程中挖出一个**只在多通道模型上才暴露**的坑。

---

## 1. ★★★★★ 那个坑：**RKNN 的输入要按 NHWC 喂**（输出仍是 NCHW）

### 症状

同一个种子、同一份权重，**torch 出的图是对的**（清晰的色块/形状），
**NPU 出的是彩色噪声**。逐点比对：

```
单次前向：eps 余弦 0.045、img 余弦 0.014   ← 几乎不相关
但数值范围却接近：torch std 1.147 vs rknn std 1.076
```

**「范围对、内容不相关」是**布局错**的典型指纹。**

### 定位过程（一步步缩小）

| 步骤 | 结果 | 排除 |
|---|---|---|
| 1. 换 **FP16（不量化）** 重转 | 余弦仍然 ≈ 0 | **不是量化误差** |
| 2. 最小复现 `Conv→SiLU→Conv` | **余弦 -0.003** | **不是 UNet 架构问题** |
| 3. 试各种输出排列（NHWC/NHCW/翻转） | 都不匹配 | 不是输出排列 |
| 4. **把输入转成 NHWC 再喂** | **余弦 +1.0000** | ★ **找到了** |

### 结论

**`RKNNLite.inference()` 的输入按 NHWC 解释**（即使 ONNX 是 NCHW 导出的）：

```python
# 输入：[N,C,H,W] → [N,H,W,C]
ins = [a.transpose(0, 2, 3, 1) for a in arrs]
o = rknn.inference(inputs=ins)[0]
# 输出**不用转**：实测 Decoder 返回 (1,3,32,32)，已经是 NCHW
```

### ★★★★★ 为什么这个坑会**藏起来**

**单通道时 `[1,1,H,W]` 与 `[1,H,W,1]` 的内存布局完全相同**（都是 H×W 个连续值）。
⇒ **单通道模型不转置也对。**

**本项目之前那个像素空间 DDPM 正是单通道**（余弦 0.9996），
所以这个坑一路没暴露；**一换到 4 通道潜空间模型，它立刻致命。**

**⇒ 教训：一个「在旧场景下验证过」的约定，换到新场景时必须重新验证 ——
   尤其是**维度含义**变了的时候（C 从 1 变成 4）。**

### 修好后的实测

| 采样步数 | torch ↔ NPU 余弦相似度 |
|---|---|
| 5 | **+0.9305** |
| 20 | **+0.9661** |

（剩余 3~7% 是量化 + 多步累积，符合预期）

## 2. ★★★★★ SD 架构端到端跑通

```
噪声 ──潜空间 DDIM(8x8x4，UNet 在 NPU)──▶ z ──VAE 解码器(NPU)──▶ 32x32x3 彩色图
```

| 指标 | 值 |
|---|---|
| UNet | 9.254 M 参数，**10.32 MB**（w8a8） |
| 解码器 | 0.193 M 参数，**0.37 MB** |
| 50 步 × 64 张（NPU） | **11.99 s** ⇒ **188 ms/张** |
| 其中解码 | 61 ms（64 张） |
| torch CPU 同任务 | 44.5 s ⇒ **696 ms/张** |
| **加速比** | **3.7×** |

**⇒ 板上只要两个模型文件（11 MB），CPU 只跑 DDIM 的算术（纯 numpy）。**

## 3. ★★★ VAE 潜空间大小：判据是**绝对大小**，不是压缩比

| 下采样 | 潜空间 | 重构 L1 | 相对误差 | 主观 |
|---|---|---|---|---|
| **8×**（3 级 stride-2） | 4×4×4 | 0.0664 | 15.5% | **明显发糊、边界丢失** |
| **4×**（2 级 stride-2） | **8×8×4** | **0.0352** | **8.2%** | **形状清晰** |

**8× 是「为 512×512 设计」的比值；照搬到 32×32 只剩 64 个数表示 3072 个值（48 倍压缩）。**
**⇒ 判据是潜空间的**绝对大小**（≥ 8×8）。**
证据图：`docs/img/vae_recon_8x_too_lossy.png`（8× 的后果）与 `docs/img/vae_recon_8x8_latent.png`（4× 的结果）。

## 4. 训练成本（CPU，16 核，batch 64）

| 阶段 | 配置 | 参数 | ms/step | 步数 | 用时 |
|---|---|---|---|---|---|
| VAE(4×) | base=16 | 0.318 M | 233 | 8000 | 30.4 min |
| 潜空间 UNet | base=64 mult=(1,2,4) | 9.254 M | 313 | 12000 | 约 63 min |
