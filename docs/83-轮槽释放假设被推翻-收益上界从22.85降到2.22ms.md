# 83 · ★ 「去一 tile 释放一轮槽」假设**被推翻**：收益上界从 22.85 ms 降到 **2.22 ms**

> 接 [docs/82](82-离线实验-去冗余拷贝的收益估算.md)（三个口径：1.48 / 4.5 / 22.85 ms）。
> 上一轮结尾我指出「乐观上界 22.85 ms 依赖一个未验证假设」，本轮**直接验证它**。

---

## 0. 假设与验证方法

**假设**（docs/82 的乐观上界用的）：
> 「去掉一个 `0x60` tile ⇒ 释放一个轮槽 ⇒ 省下一次轮的时间」

**验证方法**：把每个提交的 tile 按「每核每轮一个 tile」切成轮（`round = idx // 3`），
逐轮看这 3 个 tile 的 `op_en`：

* **纯搬运轮**：该轮 3 个 tile **全是** `0x60` ⇒ 去掉后**确定**少一轮
* **混合轮**：该轮里既有 `0x60` 又有别的 ⇒ 去掉 `0x60` 后**轮数不变**（其余 tile 仍在）

---

## 2. 修正后的收益

| 口径 | docs/82 的估计 | **本轮实测** | 性质 |
|---|---|---|---|
| 保守（纯拷贝**提交**） | 1.48 ms | 1.48 ms | 确定可实现 |
| **轮级确定释放** | — | **2.22 ms** | **本轮直接测出**（纯搬运轮 × 地板） |
| 乐观上界（全部 `0x60`） | 22.85 ms | ❌ **被推翻**（应为 2.22 ms） | 假设不成立 |
| 现实估计 | ~4.5 ms | ⚠️ 待定（可能还有**混合轮内的 tile 执行代价**未建模） |

**⇒ 收益的**确定部分**是 2.22 ms（占 9 模型总时间的 ~4.5%），
而不是 docs/82 乐观估计的 22.85 ms。差 10 倍。**

## 3. 为什么假设会错

`0x60`（搬运）tile 在命令流里**不是单独成轮的**，而是**与卷积 tile 交错**在同一轮里
（`shufflenet` 127 个混合轮 vs 0 个纯搬运轮）。

**⇒ 这说明「搬运」在 NPU 上是**与计算重叠**的** ——
这正是 docs/42 测到的「流水重叠」（权重取数被藏在计算后面）。
**搬运 tile 占着轮槽，但它与同轮的卷积 tile 并行执行。**

**⇒ 这也解释了为什么「去掉搬运能省很多」的直觉是错的**：
搬运本身可能不占额外的墙钟时间，只是占了一个发射槽位。

## 4. 教训（本轮新增）

1. **★★ 上界里的每个假设都要能单独验证，而且要尽早验证。**
   docs/82 我给了三个口径，但**没有当场验证那个最关键的假设**——
   结果它错了，而且是**10 倍**的差。**如果先验证假设，就不会给出 22.85 这个数。**
   **给区间估计时，先验证区间两端所依赖的假设。**
2. **★ 「数量多」不等于「代价大」。** `shufflenet` 的 `0x60` 占 29.1%（数量上最多），
   但**轮槽释放为 0**（代价上最少）。**我按数量排序给了优先级，那是错的排序依据。**
   **要按「代价」排序，而代价必须测，不能从数量推。**
3. **★ 与「流水重叠」对上之后，结论自洽了。** docs/42 早就测到搬运被藏在计算后面；
   本轮的「混合轮占绝大多数」正是同一件事的另一个观测。
   **两个独立观测指向同一机制时，结论的可信度大幅提高。**
