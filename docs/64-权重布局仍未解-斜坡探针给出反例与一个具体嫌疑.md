# 64 · 权重布局**仍未解**：斜坡探针给出反例，并指向一个具体嫌疑

> 接 [docs/63](63-权重布局解码成功-oc-ky-kx-ic对齐16.md)（及其修正横幅）。
> 本轮用斜坡探针（权重 = 逻辑序号）做了两级检验，**两级都不通过**。
> **如实记录：布局没解出来**，但把一个自然的假设否掉了，并锁定了一个具体嫌疑。

---

## 0. 两级检验都不通过

### 检验一（全局）：排序配对

量化若是**单调**的，则「第 k 小的字节」应配「第 k 小的浮点值」。按此推出逻辑序号：

```
oc0 的逻辑序号（按位置顺序）: [419, 428, 17] [1, 15, 60] [14, 36, 104] …
                              ↑ oc 内的逻辑序号范围是 [1, 428] —— 完全打散
```

⇒ **全局不单调。**

### 检验二（逐通道）：每个 oc 的 27 个字节 vs 该 oc 的斜坡段

```
oc   字节 min..max   取值种类   与斜坡的 Spearman
 0     2..216          25          0.412   ❌
 1     7..226          21         -0.003   ❌
 3    12..236          25         -0.429   ❌
 5    16..246          22         -0.373   ❌
 …（16 个 oc 全部 ❌，相关系数散布在 -0.43 ~ +0.66）
```

⇒ **逐通道也不单调。** 而且**同一个 oc 内字节跨度极大**（如 oc0 是 2..216）——
如果它是「27 步斜坡段的单调量化」，跨度应该很窄且单调。

---

## 1. 因此可以确定的两件事

### 1.1 `zero_point = 128` **独立确认**（这条成立）

```
浮点 0.0 → 字节 128
```

这是唯一一个在斜坡探针里**干净吻合**的点。结合 docs/62 的推断，
**权重 zero_point = 128** 现在是**实测确认**的（不再是推断）。

### 1.2 docs/63 的「块结构」是**计数级事实**，但**位置解释未被确认**

仍然成立：每 oc 占 144 字节、16 个 oc 合计 2304 = `WEIGHT_SIZE0`、每块 27 个非填充 + 117 个填充。

**但这些「27 个」落在块内的哪些位置 —— 现在被证伪了。**
（docs/63 用常值通道探针，对位置不敏感，所以那一步只能确定计数。）

## 2. ★ 一个具体的嫌疑：编译器的 `sparse_weight` 阶段

回想转换时的调用栈（第一次尝试时打印过）：

```
rknn/api/rknn_base.py → graph_optimizer.py: fold_constant
rknn/api/graph_optimizer.py:2451 in sparse_weight
rknn/api/sparse_weight.py:542 in sparse_weight
rknn/api/sparse_weight.py:83  in _range_input
```

**RKNN 编译链里有一个 `sparse_weight` 阶段**（而且它在 `build` 早期就被调用）。
如果它按稀疏性**重排/压缩**权重，那么内存里的字节顺序就**不是**逻辑张量顺序 ——
这与「全局、逐通道都不单调」的现象**一致**。

⚠️ **这是嫌疑，不是结论。** 需要下一步验证（见 §3）。

## 3. 下一步（明确、有限）

| # | 做法 | 为什么可行 |
|---|---|---|
| 1 | **用全 1 权重的探针**（所有 432 个值相同） | 若字节仍不是常数，说明有 per-element 的重排/压缩；若全是常数，说明重排只发生在层间 |
| 2 | **逐步稀疏化**：把权重按 0/1 图案布置（如只留一个通道），看非填充字节的位置如何移动 | 直接观察 `sparse_weight` 是否在动位置 |
| 3 | 用 `rknn.build(..., optimization_level=0)` 重转斜坡探针 | 若关闭优化后**变单调**，就直接证明了是某个优化 pass 在重排 |
| 4 | 对照 `--no-quant` 产物 | 分离「量化」与「布局重排」两个因素 |

**其中 #3 最省事且最有判别力** —— 一个开关就能证实/证伪「优化 pass 在重排」。

## 5. 教训（本轮新增）

1. **★ 单调性是一个很强的判据，而且一次就能否掉一整类假设。**
   「量化必然单调」是**必要条件**；用它一测，全局与逐通道都不通过 ⇒
   **立刻知道「简单布局 + 单调量化」这条路不通**，不必再猜具体排列。
   **优先找这种「一票否决」的判据。**
2. **★ 两级检验要独立做。** 全局不单调可能只是「per-channel 尺度」造成的；
   逐通道也不单调，才排除了这个解释。**同一现象往往有好几个解释，要逐个排除。**
3. **★ 反例要落到「下一步怎么做」上。** 只说「没解出来」没用；
   本轮把它变成「4 个有限步骤，其中 #3 一个开关就能证实/证伪」。
   **失败的实验要留下可执行的下一步，否则等于没做。**
4. **★ 编译链的日志值得回头看。** `sparse_weight` 这个线索一直在我自己的终端输出里
   （第一次转换失败时的调用栈），本轮才把它和「布局不单调」联系起来。
   **报错/日志里的中间阶段名，是理解产物结构的第一手线索。**
