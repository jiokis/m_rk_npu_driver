## 2. 为什么这次复现有意义

* 这两个数字此前是**在不同轮次、用不同脚本**算出来的（docs/83/88 用 `optimize.py` 之前的手写脚本）
* 本轮用**当前仓库里的工具链**（`tiling.load_segments` + `cost_model`）**从头重算**
* **⇒ 说明结论不依赖于当时那次临时脚本的实现细节**

**⇒ 这是「可复现」的证据，而不是「我当时算对了」的声明。**

## 4. 教训（本轮新增）

1. **★★ 「可复现」要明确复现的**区间**。** 我复现的是「capture → 结论」这一段，
   而「板子 → capture」没重跑。**说「已复现」而不说区间，是过度声称。**
2. **★ 用不同的实现路径重算，才叫独立复现。** 如果我用同一个脚本再跑一遍，
   那只是「重跑」不是「复现」。**本轮用的是当前仓库的工具链，与当初的临时脚本不同。**
3. **★ 逐位一致比「接近」更有价值。** 2.11 与 12.83 都是精确复现 ——
   **说明这两个结论对实现细节不敏感，是稳健的。**
