# 80 · 结构级时序模型落地：**地板主导区间可靠**，加带宽项后仍有一半模型未解释

> 接 [docs/79](79-结论-完整权重布局在当前工具条件下不可得-仿真器转向.md)（转向不依赖布局的部分）。
> 本轮把已验证的时序结论落成 `src/sim/rknpu/timing.py`，并在 **9 个真实模型**上验证。

---

## 0. 模型

```
t_total ≈ max( n_submit × FLOOR ,  traffic / BW )  +  MAC_total / PEAK

  PEAK   = 1.024 T-MAC/s/核（阵列 32×32 @1GHz）        docs/44
  FLOOR  = 67.4 µs/提交（细碎提交模型实测 49~71）      docs/59
  BW     = 23.84 GB/s（实测 DDR 上限）                 docs/55
  traffic= Σ(权重 + 输入特征 + 输出特征)
```

**⇒ 只需要命令流结构（提交数、tile 数、tile 的 MAC 量、各缓冲尺寸），不需要权重布局。**

## 2. 诚实结论

**✅ 成立的**：
* 模型在**地板主导**区间（提交数 ≥63）可靠：**误差 −0.2% ~ +13.4%**
* 加带宽项把带宽主导的模型从 −73%/−78% 改善到 −33%/−16%
* 形式简单、只吃命令流结构 ⇒ **可用于离线实验**

**❌ 不成立的**：
* **4 个模型仍低估 35~56%** ⇒ **有第三个分量未建模**
* 不能声称「时序模型已建成」——它目前只在**一个区间**可靠

**⇒ 我把适用边界写进了模块的 docstring，避免被误用。**

## 4. 教训（本轮新增）

1. **★ 把「适用边界」写进代码的 docstring，而不是只写在文档里。**
   这个模型只在「地板主导」区间可靠 —— **如果不说，使用者会在带宽区间误用它**。
   **模型的边界要和模型放在一起。**
2. **★ 分区间看误差，不要只看平均。** 9 个模型的平均误差会掩盖「3 个很准 + 4 个很差」。
   **按机制分组再看误差，才能看出模型在哪里成立。**
3. **★ 没有达到目标时，交付「有边界的可用部分 + 明确的缺口」。**
   本轮没建成通用时序模型，但交付了：一个在特定区间可靠的预测器、
   一个把误差从 −73% 改善到 −33% 的带宽项、以及**4 个未解释模型的共同特征线索**。
   **这比「时序模型还在做」有用得多。**
