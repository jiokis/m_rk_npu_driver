# 79 · 结论：**完整权重布局在当前工具条件下不可得** —— 仿真器转向不依赖它的部分

> 接 [docs/78](78-维度顺序搜索TOI胜出但每通道分组是错的.md)。上轮我承诺：
> 「如果 `hybrid_quantization_step2` 也不通，我会明确说『在当前工具条件下，
> 从 DRAM 字节反推完整布局不可行』，并把仿真器的工作重心转到不依赖完整布局的部分。」
> **本轮验证了它不通，现在兑现这个承诺。**

---

## 1. `step2` 不通

```
hybrid_quantization_step2(model_input='probe6.model', data_input='probe6.data',
                          model_quantization_cfg='probe6.quantization.cfg')
  ⇒ ret = 0（构建成功）
  ⇒ 产物：只有 step1 那三个文件，**没有新的带名字的权重文件**
```

**⇒ 它只在内存里构建模型，不导出可读的结构。这条路关闭。**

---

## 2. 已尝试并排除的路径（`oc` 布局）

| # | 路径 | 结果 |
|---|---|---|
| 1 | one-hot 探针（docs/62） | ❌ 与量化机制冲突 |
| 2 | 每通道常数探针（docs/62/77） | ❌ **per-channel 量化把通道内常数压平**（432 槽全同值） |
| 3 | 稀疏斜坡（probe4，docs/68） | ⚠️ 通过但**对 oc 排列不敏感**（15/16 通道全零） |
| 4 | 密集斜坡 + 候选枚举（docs/76/78） | ⚠️ `TOI` 胜出但 max 误差 0.558 不合格 |
| 5 | 逐通道 scale（docs/78） | ❌ 拟合**更差**，与「每通道满量程」互斥 ⇒ 分组错误 |
| 6 | 12 种维度顺序系统搜索（docs/78） | ❌ 全部不合格（最好 0.558） |
| 7 | `hybrid_quantization_step2`（本轮） | ❌ 不导出可读结构 |

**⇒ 7 条路径，全部排除。这是「在当前工具条件下不可得」的依据。**

---

## 3. ✅ 已经确证的部分（这些仍然成立、且可复用）

| 项 | 依据 |
|---|---|
| 权重在 DRAM 的位置 | 寄存器 `0x1110`（基址）+ `WEIGHT_SIZE0`（长度） |
| `WEIGHT_SIZE0 = kh·kw·out_ch·align(in_ch,16)` | **三个独立算例**（probe4 2304 / probe5 conv 288 / probe5 Gemm 4096） |
| 每 tap 内前 `in_ch` 槽是真实值、其余填 `128` | probe4/probe7 直接读到 |
| **`out_ch=16` 且 `ky` 优先时**，`offset = (ky*kw+kx)*256 + oc*16 + ic` **能重建到量化精度** | docs/68/70：**99.5% 落在 ±scale/2 内** |
| 反量化公式 | docs/69：`w = (q_signed+128)*scale`，27/27 完美拟合 |
| byte 语义 | `0`=精确零 / `128`=不存在的通道 / 其它=量化值 |
| 输入布局 | docs/71：原始 uint8、NHWC、偏移 0，**逐字节 100%** |

**⇒ 「在 `out_ch=16`、稀疏权重」这个范围内，布局是可用的**（docs/70 已验证 99.5%）。
**不可得的是「任意 `out_ch`、任意权重分布下的普遍布局」。**

---

## 4. 仿真器的转向：做**不依赖完整布局**的部分

| 部分 | 是否依赖完整布局 | 状态 |
|---|---|---|
| ① DRAM 镜像抓取 | 否 | ✅ |
| ② 命令流解码 / tiling / 地址映射 | 否 | ✅ 已有 22 个分析工具 |
| ③ 输入布局 + 激活量化参数 | 否 | ✅ |
| ④ 权重反量化（`out_ch=16` 范围） | 部分 | ✅ docs/70 |
| ⑤ **结构级时序模型** | **否** | ⬜ **← 应转向这里** |
| ⑥ **命令流结构分析 / 离线实验** | **否** | ⬜ **← 和这里** |
| ⑦ 通用数值仿真（任意模型） | **是** | ❌ **受阻于布局** |

**⇒ ⑤⑥ 完全不依赖权重布局，而且它们正是「高自由度开发」最需要的部分**
（去冗余拷贝、合并提交、改 tiling —— 这些实验**只需要命令流结构，不需要权重数值**）。

**⇒ 转向 ⑤⑥ 是「在当前约束下最大化价值」的选择。**

---

## 5. 教训（本轮新增）

1. **★★ 承诺的「止损条件」要兑现，不能因为舍不得沉没成本而继续。**
   上轮我写下「如果 step2 不通就明确说不可行并转向」——本轮它不通，**我按承诺转向**。
   **在开始一条路之前写下止损条件，比事后判断「要不要继续」可靠得多。**
2. **★ 七条路径的「排除」本身就是成果。** 我现在能明确说
   「**在 `out_ch=16` 的范围内布局可用（99.5%），但普遍布局不可得**」——
   这是一个有边界的、可引用的结论，比「还在试」有用。
   **把「不可得」写成带条件的结论，而不是「失败」。**
3. **★ 转向不等于放弃。** 仿真器的价值不只在「逐元素数值复现」——
   **时序模型与命令流离线实验完全不需要权重布局**，而且它们才是
   「让开发不再依赖硬件试错」这个**原始目标**的直接答案。
   **我一度把「数值仿真」当成了仿真器的全部，这是目标偏移。**
