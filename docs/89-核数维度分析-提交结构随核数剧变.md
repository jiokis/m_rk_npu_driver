# 89 · 核数维度分析：**提交结构随核数剧变**（同一模型 4 次 vs 77 次提交）

> 接 [docs/88](88-优化分析器落地-可复用工具.md)（工具落地）。
> 本轮用工具跑已有的 `cm1/cm3/cm7` 语料（**同一个模型 yolov5s，只改核数**），
> 得到第三个优化维度，也**顺带解释了时序模型为什么跨核数不成立**（docs/55）。

---

## 0. 结果

```
指标            cm1(1核)    cm3(2核*)   cm7(3核*)
提交数              4          77          77
tile 数           615         413         428
轮数              615         164         100
tile/提交       153.8         5.4         5.6
纯搬运轮           58           8           2
可删重复写搬运      45          53          80
```
（*`cm3`/`cm7` 是 core_mask 取值，对应 2/3 个核）

---

## 1. ★ 最醒目的：提交数 4 vs 77

**同一个模型，只改核数，提交数差 19 倍。**

* **1 核**：4 次提交，**153.8 tile/提交** —— 编译器做了**极其激进**的融合
* **2/3 核**：77 次提交，**5.4 tile/提交** —— 碎片化

**⇒ 编译器的 tiling/融合策略随核数**改变**，不只是「同样的切分分到更多核上」。**

这解释了两件旧事：
* **docs/55**：时序模型**跨核数不成立**（cm=3 误差 −31.7%）——
  因为**命令流结构本身就变了**，不是同一个结构换了核数
* **docs/59**：`cm1` 的轮数 615、`cm3` 208、`cm7` 145 —— 同一现象的另一面

---

## 2. 纯搬运轮随核数**减少**（58 → 8 → 2）

```
cm1: 58 个纯搬运轮      cm3: 8      cm7: 2
```

**⇒ 核数越多，搬运 tile 越倾向于**与计算混在同一轮**（docs/83 的「混合轮」现象）。**

**⇒ 这进一步支持 docs/42/83 的「流水重叠」结论**：
多核时搬运被更充分地藏在计算后面。

---

## 3. 可删的重复写搬运随核数**增加**（45 → 53 → 80）

**⇒ 与 docs/47/50 的实测完全一致**：冗余拷贝 = `27 ops × cores`
（1 核 46 遍 / 2 核 54 遍 / 3 核 81 遍，docs/47）。

**⇒ 工具独立复现了这个规律**（45/53/80 vs 47 的 46/54/81）——
**两个独立方法得到同一结论 ⇒ 可信度大幅提高。**

---

## 4. 对「合并提交」收益的影响

```
提交数减 25% / 50% / 75% 的收益：
  cm1: 0.07 / 0.13 / 0.20 ms      ← 只有 4 次提交，没什么可减
  cm3: 1.30 / 2.59 / 3.89 ms
  cm7: 1.30 / 2.59 / 3.89 ms
```

**⇒ 1 核时「合并提交」几乎没有收益（只有 4 次提交）——编译器已经融到极限了。**
**⇒ 合并提交的收益**只存在于多核**（因为多核时编译器变保守了）。**

**这是一个反直觉但有依据的结论**：想省提交地板，**先看看单核是怎么做的**——
单核的融合度（153.8 tile/提交）远高于多核（5.4），
**说明编译器有能力融合，只是多核时没这么做。**

---

## 5. 教训（本轮新增）

1. **★★ 一个维度上的「结构不变」是假设，不是事实。** 我一直把「核数」当成
   「同样的命令流分到更多核」——**实测是命令流本身变了（4 → 77 次提交）**。
   **改变任何一个配置，都要先验证「结构是否不变」。**
2. **★ 工具能独立复现旧结论 ⇒ 可信度提升。** 可删重复写 45/53/80 与 docs/47 的 46/54/81
   吻合 ⇒ 两条独立路径得到同一规律。**新工具的第一件事就是去对旧结论。**
3. **★ 反直觉结论要留着。** 「单核融合度 153.8 tile/提交，多核只有 5.4」——
   这意味着**编译器有能力做更激进的融合但多核时没做**。
   这不是「优化空间」的证明（可能有正确性/同步原因），但**它是一个具体的、可追问的问题**：
   *为什么多核时编译器变保守了？*
