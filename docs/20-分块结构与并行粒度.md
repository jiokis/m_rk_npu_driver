## 一、一个必须先回答的问题

我此前把「同一 `op_idx` 的连续 task」叫作一个"算子"。
但它内部有多个段（平均 2.7 个，最多 19 个）——**这些段是什么关系？**

两种可能，含义完全不同：

| 假设 | 含义 | 并行含义 |
|---|---|---|
| A. 同层分块 | 一个层被切成 N 块 | **各块独立 ⇒ 可跨核并行** |
| B. 同类型不同层 | N 个不同的层恰好同类 | 它们是串行依赖的 |

## 二、判据与结论

**判据**：若是同层分块，各块的**输出形状应当一致**（只是数据位置不同）。

**结果（决定性）**：

```
各算子的「输出宽（CORE 0x3014 低16）」是否唯一：
   ✅ 唯一（= 同层分块）: 173
   ❌ 多个（= 不同层）  : 0        ← 零个例外
   无该字段              : 48
```

**⇒ 173/173 全部是「同层分块」，假设 A 成立。**

### 佐证：每块有独立的输入/输出地址

| op | 分块 | 输出宽 | 通道 | CNA 特征地址（每块不同） | DPU 输出地址（每块不同） |
|---|---|---|---|---|---|
| op1 | 0 | 320 | 32 | `0xfef77000` | `0xff1cf000` |
| op1 | 1 | 320 | 32 | `0xfef86f00` | `0xff1e4400` |
| op1 | 2 | 320 | — | `0xfef96e00` | `0xff1f9800` |
| op3 | 0 | 160 | 64 | `0xff4ef000` | `0xff0a3000` |
| op3 | 1 | 160 | 64 | `0xff518400` | `0xff0ada00` |

- `CNA 0x1070` 的取值个数 **== 分块数**（op1 的 19 块 → 19 个不同输入地址）
- `DPU 0x4020` 同理
- 地址按**固定步长**递进（op1 输入步长 `0xff00`，op3 为 `0x29400`/`0x2a800`）
- **只有前 1~2 块写形状寄存器**，其余块只更新地址（继承形状）

⇒ **每块是独立的数据切片，读自己的输入、写自己的输出。**

## 三、分块规模统计

| 每算子分块数 | 算子数 |
|---|---|
| 1 | 68 |
| 2 | 67 |
| 3 | 48 |
| 4 / 5 | 10 / 14 |
| 6 / 7 | 2 / 3 |
| 10 | 8 |
| 19 | 1 |

**221 个算子 → 588 个分块（平均 2.7）**

### 分块**不是**按 3 核切的

```
分块数 mod 3:  0→50 个算子 · 1→90 · 2→81
能被 3 整除:   50 / 221 = 23%
```

⇒ 分块依据是**内存/形状约束**，不是核数。

## 四、★ 这改写了利用率结论

### 4.1 旧结论要重新解读

docs/19 说"相邻段重叠空间只有 16%，所以核内优化天花板低"。**这个数字仍然成立，
但解读变了**：

- 我比较的"相邻段"**其实是同一层的相邻分块**，它们当然用同样的流水级（都调 CNA）
- 所以"16%"衡量的不是"层间能否重叠"，而是"**同层相邻分块在同一核上能否重叠**"
- 结论依旧：**在同一核内，分块之间没有重叠空间**（都抢同一个 CNA）

### 4.2 真正的并行粒度是「分块」，不是「层」

```
588 个独立分块  ← 这才是可并行的粒度
221 个层        ← 层内是分块的集合
```

**每块独立读写自己的数据 ⇒ 天然可跨核分发。**

如果 3 个核各跑一批分块，理论加速上限接近 3×（受带宽与依赖限制）。
这与我此前抓取时**只开 1 个核**（`core_mask=0x1`）形成鲜明对比 ——
**2/3 的算力是被闲置的**。

### 4.3 但仍有一个未解的关键问题

分块不是按 3 切的（23% 整除率）。那么 librknnrt 在 `core_mask=0x7` 时**到底怎么用多核**？

| 可能 | 验证方式 |
|---|---|
| 把 588 个分块轮转分给 3 核 | 重抓 cm=7，看任务切分是否变化 |
| 把分块再细分到核 | 看 task 数是否变为约 3 倍 |
| 只在层边界粗粒度分工 | 看 submit 次数是否变化 |
| **根本不并行**（多核只用于多模型/多流） | 对比 cm=1 与 cm=7 的耗时 |

**这是步骤 1 要回答的核心问题**，而且现在问题的形式比之前精确得多。

## 五、对"最大程度利用 NPU"的更新版结论

| 杠杆 | 上限 | 说明 |
|---|---|---|
| **跨核并行分块** | **接近 3×**（未验证） | 588 个独立分块 × 3 核；**最大杠杆** |
| 核内调度 | ~16% | 同层分块抢同一 CNA，只能靠层边界处的 PPU 填充 |
| 利用闲置的 PPU | 小 | PPU 仅占 10% 的段 |
| 减少配置带宽 | 未知 | 相邻段 89% 配置相同，取决于硬件有无配置缓存 |

**优先做跨核** —— 这条结论现在有明确的数据支撑（588 个独立分块、平均 2.7/层、只开 1 核）。
