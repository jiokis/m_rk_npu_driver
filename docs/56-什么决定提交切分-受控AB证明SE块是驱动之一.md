# 56 · 什么决定提交切分：**受控 A/B 证明 SE 块是驱动之一**（并否掉两个假设）

> 接 [docs/55](55-9个真实模型横向对比-两种完全不同的瓶颈.md)。那里的最大空白是：
> **为什么有的模型 3 次提交、有的 183 次？** 本轮用**受控实验**回答了其中一类。
>
> 工具：`deploy/make_onnx_models.py` 新增 `ab_se` / `ab_nose` 两个受控模型

---

## 0. ★ 决定性结果：受控 A/B —— 唯一变量是 SE 块

**同一骨干**（6 个 3×3 conv + BN + ReLU + 池化 + FC），**唯一变量**是有没有 SE 块
（全局平均池化 → Sigmoid → 逐通道相乘）：

| 模型 | 提交数 | hw | bins |
|---|---|---|---|
| `ab_se`（**有** SE） | **25** | 4819 µs | 134 |
| `ab_nose`（**无** SE） | **7** | 2916 µs | 54 |
| **差异** | **3.6×** | **1.65×** | 2.5× |

**⇒ SE 块（全局归约 + 广播乘）会把提交数放大 3.6 倍。**

这解释了 `efficientnet_b0` 为什么是 88 次提交（它有 **17 个 SE 块**，
`GlobalAveragePool×17 + Mul×65 + Sigmoid×65`），而 `mnasnet0_5`/`mobilenet_v2`
（只有 Relu/Clip、无 SE）能融进 **3 次提交**。

### 为什么 SE 会断提交（机制推测）

SE 需要把**整个特征图归约成一个 1×1×C 的向量**，再**广播乘回**原图 ——
这要求前一层**全部算完**才能开始，是天然的**全局同步点**。
而卷积链可以流式流水（下一层的 tile 不必等上一层全部完成）。
⚠️ **这是推测**；实测到的只有「加 SE ⇒ 提交 7→25」这个因果。

## 1. 两个被**明确否掉**的假设

在找到 SE 之前，我试了两个更自然的解释，都量化后否掉了：

### 假设 A：布局算子（Concat/Reshape/Transpose）逼出提交边界

```
逐个 ONNX 数布局算子 → 回归「提交数 ~ 布局类/Conv」：
  R² = 0.040  (n=9)   ⇒ 否掉
反例：regnet_x_400mf 与 efficientnet_b0 **零布局算子**，却发 113 / 88 次提交
```

### 假设 B：分组/深度可分离卷积逼出提交边界

```
统计每个模型的 Conv group 属性 → 回归「提交数 ~ 分组卷积占比」：
  R² = 0.016  (n=9)   ⇒ 否掉
反例：mnasnet0_5 / mobilenet_v2 各有 17 个 depthwise，只有 3 次提交；
      shufflenet_v2_x0_5 有 19 个，却有 63 次提交
```

**两个假设都写出来、量化、否掉了。** 这排除了一整类解释，比「没找到原因」有用。

---

## 2. 提交边界的结构：「大包 + 边界小提交」

看实际切分（regnet_x_400mf 前 12 次）：

```
[1..6|n=9] [6..6|n=2] [7..11|n=9] [11..16|n=9] [16..19|n=6] [20..26|n=12]
[26..26|n=4] [27..30|n=15] [31..41|n=15] [41..41|n=6] [41..46|n=12] [46..46|n=4]
```

**模式：一个大包（覆盖多个 op_idx）+ 一个小的边界提交，而且边界提交的 op_idx
出现在前一个包的末尾。** 与 docs/54 在 `dwsep` 上看到的「一大包 + 单 tile 提交」是同一个形状。

`mnasnet0_5` 是另一极：

```
[1..54|n=159]  ← 一次提交装了 54 个 op_idx、159 个 tile
[49..49|n=1] [50..54|n=6]
```

**⇒ 编译器对「可流水的卷积链」融合得非常激进（54 op → 1 提交），
对「有全局同步点的结构」则近乎一 op 一提交。**

## 4. 仍然没解释的

| # | 未结项 | 说明 |
|---|---|---|
| 1 | **`regnet_x_400mf` 为什么 113 次提交** | 零 SE、零布局算子、只有 Relu+Add+分组卷积 —— 三种已知解释都不适用。**这是最该追的下一个** |
| 2 | `densenet121` 183 次（Concat×62 + BN×62） | Concat 假设在横向上被否掉（R²=0.04），但 densenet 的 Concat 密度极高，可能是**阈值效应**而非线性关系 |
| 3 | SE 的机制（全局同步点） | 目前是推测；可用「SE 但去掉 Sigmoid」或「SE 但用局部池化」做进一步受控实验 |

## 5. 可操作的结论（针对具体模型）

**对 SE 类模型（`efficientnet_b0` 等）：**
SE 块是提交数的驱动 ⇒ **把 SE 换成「局部池化」或「去掉全局归约」能显著减少提交**。
按本轮受控实验的比例（提交 7→25、时间 1.65×），反向操作在 efficientnet 上
有把 88 次提交降到 ~30 次的潜力 ⇒ 按 docs/55 的账（地板占 64% = 6 ms），**可能省 3~4 ms**。
⚠️ 代价是**精度**（SE 是有效结构），所以这是**精度换速度**的权衡，不是白拿的。

**对可融合的卷积链（`mnasnet`/`mobilenet_v2`）：**
已经被融到 3 次提交，**没有提交侧空间**；它们撞的是带宽墙（docs/55）。

**对 `regnet_x_400mf`：**
提交数异常（113）但原因不明 ⇒ **先别动**，等找到原因再说。

## 6. 教训（本轮新增）

1. **★ 能自己造模型，就能做受控实验 —— 这是本阶段最大的方法论升级。**
   前面三轮都在「观察 9 个现成模型的差异」，只能做相关；
   这一轮我把 SE 作为**唯一变量**做 A/B，直接得到**因果**（7→25 提交）。
   **相关看现象，受控看原因。**
2. **★ 否掉两个假设和找到一个原因同等重要。** 布局算子（R²=0.04）与分组卷积（R²=0.016）
   都写出来、量化、否掉了。**如果没有这一步，我会一直盯着 Concat 打转。**
3. **★ 受控实验的变量要真的只有一个。** `ab_se` 与 `ab_nose` 共用同一个 `_ab_common()`
   骨干函数，唯一差别是 `se=True/False` —— 这样 7→25 才归因得干净。
4. **推测与实测要分开写。** 「SE 造成全局同步点」是推测，「加 SE 提交 7→25」是实测，
   文档里分开标注了。

## ⚠️ 修正（由 [docs/57](57-受控AB第二轮-分组卷积是驱动Add不是-并推翻上轮一个否证.md) 给出）

本篇 §1 用**跨模型相关性**否掉了两个假设。**其中「分组卷积」那条是错的**：

```
本篇： 跨 9 个真实模型「提交数 ~ 分组卷积占比」⇒ R² = 0.016 ⇒ 判为「否掉」
docs/57：受控 A/B（同一骨干，唯一变量 group=8）⇒ 提交数 **7 → 13（1.86×）**
         ⇒ **分组卷积确实是驱动**
```

**错在方法**：跨模型相关性有大量混杂因素，真实效应会被淹没。
`mnasnet0_5`/`mobilenet_v2` 只有 3 次提交不是因为「depthwise 不断提交」，
而是因为**整体可融合**（无 SE、无分组、无 Concat），把分组卷积的效应盖住了。

**⇒ 跨模型相关性可以用来「发现线索」，不能用来「否证机制」。**
