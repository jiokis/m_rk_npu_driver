# 134 · ★★★★★ 每个 task 映射回算子：**模型被复制 3 份（每核一份，权重各一份）**

> 接 [docs/133](133-运行侧提交结构-329次提交全部服从3核提交任务数必为3的倍数.md)。
> docs/133 只看清了「提交」层。本轮往下一层：**把每个 task 映射回算子**。

## 1. ★★★★ 靠一个寄存器打通映射：`CNA(513).4136 = 空间尺寸`

把 74 个 task 的 `CNA.4136` 按执行顺序排出来：

```
79:112  80:-  81:-  82:56 83:56 84:56 85:56  86:28 87:28 88:28 89:28 90:28
91:14 92:14 93:14 94:14 95:14  96:7 97:7 98:7 99:7 100:7  101:- 102:1 103:1 104:-
105:112 106:- 107:56 108:56 109:56 110:56 111:28 112:28 113:28 114:28 115:28
116:14 117:14 118:14 119:14 120:14 121:7 122:7 123:7 124:7 125:7 126:- 127:1 128:-
129:112 130:- 131:56 132:56 133:56 134:56 135:28 … 145:7 … 151:1 152:-
```

**⇒ 取值序列 `112, 56×4, 28×5, 14×5, 7×5, 1` 与 resnet18 的特征图**逐一对应**：**

| 段 | 空间 | task 数 | resnet18 里对应的 |
|---|---|---|---|
| 79 | 112 | 1 | stem conv（stride 2 后输出 112） |
| 82–85 | 56 | **4** | layer1 = 4 个 conv ✅ |
| 86–90 | 28 | **5** | layer2 = 3 + 2（含 downsample）✅ |
| 91–95 | 14 | **5** | layer3 ✅ |
| 96–100 | 7 | **5** | layer4 ✅ |
| 102–103 | 1 | 2 | GAP conv + fc conv ✅ |

**⇒ 一个 task = 一个算子在**一个核上**的一次执行。**
**（这也是「IR 里 22 个像 Conv 的 NPU 算子」在运行侧的对应物。）**

`CNA(513).4368`（输入张量地址）随 task **单调递增**，且约等于上一个 task 的 RDMA 输出地址（差 512）⇒ **地址链独立印证了算子顺序。**

## 2. ★★★★★ 最重要的发现：**序列重复了 3 次，且权重各不相同、输入相同**

```
task  79（第 1 遍）: 权重 = 4282006528   输入 = 4283531264
task 105（第 2 遍）: 权重 = 4282074624   输入 = 4283531264   ← 权重不同，输入**相同**
task 129（第 3 遍）: 权重 = 4282140928   输入 = 4283531264   ← 权重又不同，输入仍相同
```

**⇒ 与 pass 清单里的 `RKNNDuplicateWeightPass`（权重复制）与 `RKNNMultiSurfacePass`（多 surface）一致：
   **权重复制 3 份（每核一份），三个核读同一份输入、各处理一片数据。****

### 全模型验证：每个模型的 task 序列都分成 3 段，且后两段几乎等长

| 模型 | 各段 task 数 | 后两段 |
|---|---|---|
| resnet18 | 26 / 24 / 24 | 24, 24 |
| mnasnet0_5 | 54 / 53 / 53 | 53, 53 |
| mobilenet_v2 | 54 / 53 / 53 | 53, 53 |
| squeezenet1_0 | 65 / 60 / 60 | 60, 60 |
| shufflenet_v2_x0_5 | 187 / 156 / 156 | 156, 156 |
| densenet121 | 902 / 835 / 835 | 835, 835 |
| regnet_x_400mf | 1302 / 921 / 921 | 921, 921 |

**⇒ 后两段**完全相等**（24/24、53/53、60/60、156/156、835/835、921/921）——
   **这正是「3 个等分 surface」该有的样子。**
**⇒ 第一段多出来的部分，正好是**只在单核上跑的那些算子**（见 §3）。**

⚠️ **标记为「强指示」而非「已证明」**：`DPU(4097).16416` 的语义尚未独立确认
（我叫它「权重地址」是因为它在三次重复中不同、且与 `RKNNDuplicateWeightPass` 对得上）。

## 3. ★★★★★ 恒等式：`Σtasks = 3 × P + S`（9/9 模型**精确**成立）

* `P` = 3 核提交的轮数之和（= Σ`m0x7` 的 `task_number` / 3）
* `S` = 1 核提交的任务数之和

| 模型 | P（并行槽） | S（串行槽） | 3P+S | Σtasks | 一致 |
|---|---|---|---|---|---|
| resnet18 | 24 | 2 | 74 | 74 | ✓ |
| mnasnet0_5 | 55 | 1 | 166 | 166 | ✓ |
| mobilenet_v2 | 56 | 1 | 169 | 169 | ✓ |
| squeezenet1_0 | 62 | 5 | 191 | 191 | ✓ |
| googlenet | 124 | 30 | 402 | 402 | ✓ |
| shufflenet_v2_x0_5 | 156 | 31 | 499 | 499 | ✓ |
| regnet_x_400mf | 922 | 381 | 3147 | 3147 | ✓ |
| densenet121 | 835 | 67 | 2572 | 2572 | ✓ |
| efficientnet_b0 | 45 | 183 | 318 | 318 | ✓ |

**⇒ 9/9 精确。** 而且 **`S` 恰好等于「第一段比后两段多出来的 task 数」**
（resnet18 2、mnasnet 1、mobilenet 1、squeezenet 5、shufflenet 31、densenet 67、regnet 381 —— 与 §2 的表逐一对上）。

**⇒ 所以 task 的来源是**两条**：
   ① **并行部分**：每个算子 × **3 个核**各一个 task
   ② **串行部分**：只在 **1 个核**上跑的那些算子（每算子一个 task）**

**⇒ 这也解释了 docs/133 的「轮数 ≈ 算子数」（1.02~1.09）为什么只在三个模型上成立：
   那三个模型的 `S` 很小（1~2），`P` 基本就是「算子数 × 1 轮」。**

## 4. ★★ 提交 = **图被切成的段**（现在结构清楚了）

resnet18 的 5 次提交：

| 提交 | 核掩码 | 任务数 | 每核算子数 |
|---|---|---|---|
| 1 | 0x7 | 6 | 2 |
| 2 | **0x1** | 1 | 1（串行） |
| 3 | 0x7 | 60 | 20 |
| 4 | **0x1** | 1 | 1（串行） |
| 5 | 0x7 | 6 | 2 |

**⇒ 图被切成 5 段：`[2 算子×3核] [1 算子×1核] [20 算子×3核] [1 算子×1核] [2 算子×3核]`**
**⇒ 每核算子总数 = 2+1+20+1+2 = 26**（与 §2 的第一段 26 对上）。

**⇒ 提交数 = 段数。而「怎么切段」仍**未**解出**（这是目标②最后一块）。

## 5. 现在能说什么（边界）

**已验证**：

1. **一个 task = 一个算子在一个核上的一次执行**（`CNA.4136` 与特征图逐一对应）
2. **模型被复制 3 份**（权重 3 份、输入共享；后两段 task 数完全相等）
3. **`Σtasks = 3P + S`（9/9 精确）**
4. `CNA.4136` = 空间尺寸；`CNA.4368` = 输入张量地址（单调递增，与 RDMA 输出地址相接）
5. 提交只有 `0x7` / `0x1` 两种核掩码（docs/133）

**未解决**：

* **图怎么被切成段**（= 提交数从哪来）—— 目标②最后一块
* `DPU.16416` 的确切语义（权重的判定是**强指示**，不是证明）
* `P`（并行轮数）与 IR 算子数的关系（resnet18 24 vs 22；densenet121 835 vs 246 ⇒ 每个算子可能占多轮）

## 7. 教训（本轮新增）

1. **★★★★★ 一个「语义明确的寄存器」能顶一整套逆向。**
   我只确认了 `CNA.4136 = 空间尺寸`（靠它取值序列与 resnet18 特征图逐一对应），
   就立刻得到了「一个 task = 一个算子」这个关键映射。
   **⇒ 找那个「取值序列能对上已知结构」的寄存器。**
2. **★★★ 「重复 3 次」不是噪声，是**结构**。** 序列重复三次很容易被当成「跑了三次」；
   但**后两段完全等长**（24/24、53/53、835/835）说明它是**3 个等分 surface**，不是三次推理。
   **⇒ 看到重复时，去比较各段**长度**——等长说明是并行副本，不等长说明是不同阶段。**
3. **★★★ 恒等式比相关性有力得多。** `Σtasks = 3P + S` 在 9 个模型上**精确**成立
   （不是「R² 很高」）——**这种「算得出来、对得上」的等式才是机制证据。**
4. **★ 我把「权重地址」标成强指示而非结论。** `DPU.16416` 我只是**推断**它是权重地址；
   判据写在 §6 #1（改一处权重看它变不变）。**推断必须附判据。**
