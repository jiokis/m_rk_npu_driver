## 1. 数据（`probe4`：只有 oc0 非零，斜坡 1..27）

```
(浮点 w, 有符号字节 q, 无符号字节 byte)
   w= 1  q=-119  byte=137
   w= 2  q=-109  byte=147
   w= 3  q=-100  byte=156
   w= 4  q= -90  byte=166
   w= 5  q= -81  byte=175
   w= 6  q= -71  byte=185
   …
```

**取法**：`byte = DRAM[(ky*3+kx)*256 + 0*16 + ic]`，`q = byte − 256·(byte ≥ 128)`，
`w = ic*9 + ky*3 + kx + 1`。

### ★ 为什么「取有符号」是对的 —— 8 位回绕被公式解释了

docs/68 发现 `ic=1` 的序列是 `222,232,241,251,4,14,23,33,42`，其中 `251 → 4` 看起来是断裂。
**取有符号后**：`-34,-24,-15,-5,4,14,23,33,42` —— **完全连续，步长 9.45**。

**⇒ 那个「回绕」不是异常，而是 int8 的正常溢出。**
（`251 + 9.45 = 260.45 → 260 − 256 = 4`。）

## 2. 一个附带结论：**同一个权重张量里，三个 ic 共用一套 scale/zero_point**

docs/68 末尾我留了个疑问：三条 ic 序列「步长相同但起点不同」，怀疑是 per-ic 量化。

**拟合后这个疑问消掉了**：三条序列的起点差异，**完全由「它们对应的浮点值域不同」解释**
（ic=0 → w∈[1,9]；ic=1 → w∈[10,18]；ic=2 → w∈[19,27]）。
用**同一套** `(zp=−128, scale=0.105814)` 代进去，**27 个点全部复现**。

**⇒ 至少在这个张量上是 per-tensor 量化，不是 per-ic。**
（不排除大模型上会用 per-channel；但那不影响公式形式。）

## 4. 教训（本轮新增）

1. **★★ 布局定下来之后，量化参数不必去别处找 —— 回归就行。**
   我在 docs/67 花了力气去控制块里找 scale 表（还找错了）。
   **正确做法**：我同时知道「浮点权重」和「量化字节」，**那就是一个 27 点的线性回归**。
   **有输入有输出时，参数是可以解出来的，不需要去读它的存放位置。**
2. **★ 取有符号这件事，把「异常」变成了「证据」。** docs/68 里 `251 → 4` 是「8 位回绕」；
   本轮取有符号后它变成连续的 `-5 → 4`。**同一个现象，换个表示就从噪声变成确认。**
3. **★ 拟合的完美程度本身就是判据。** 27/27、残差 0.00 ——
   如果布局错一个维度，不可能全部吻合。**残差为零比「看起来合理」强得多。**
4. **★ 上一轮留的疑问，本轮被同一份数据回答了。** docs/68 怀疑 per-ic 量化；
   本轮用同一套参数复现全部 27 点 ⇒ 疑问消掉。
   **不要把「留待确认」当成结论写进文档** —— 它可能只是没算。
