# 81 · 给 `0x18`/`0x60` tile 计代价的修正**被否掉**（系数非物理）

> 接 [docs/80](80-结构级时序模型落地与验证-边界诚实.md)。上轮留下 4 个未解释模型，
> 我怀疑是 `0x18`（elementwise）/`0x60`（搬运）的 tile 代价没算进去。**本轮验证：这个修正是错的。**

---

## 2. 拟合结果：**系数非物理**

```
最小二乘拟合 (0x18, 0x60) 单价 = (-2.56, +17.18) µs/tile
                                  ↑ 负的！不可能
```

**⇒ `0x18` 的系数是负的** —— 意味着「elementwise tile 越多，时间越短」，
这**在物理上不可能**。**⇒ 模型形式错了，不是参数没调好。**

## 3. 逐模型效果：有改善也有**大幅恶化**

```
模型                        原误差     新误差
mnasnet0_5                 -30.5%   -17.9%  ✅
mobilenet_v2               -11.4%    -2.2%  ✅
shufflenet_v2_x0_5          +9.5%   +65.4%  ❌❌ 大幅恶化
resnet18                   -38.3%   -29.1%  ✅
squeezenet1_0              -45.3%   -17.9%  ✅
googlenet                  -56.2%   -37.9%  ✅
regnet_x_400mf              -0.2%    +7.2%  ⚠️ 由准变差
efficientnet_b0            -35.6%   -25.6%  ✅
densenet121                -13.4%    -2.6%  ✅
```

**`shufflenet` 从 +9.5% 恶化到 +65.4%** —— 它原本是**最准的**模型之一，修正后变成最差的。
**⇒ 这个修正用「牺牲已经准的模型」换取「改善不准的模型」，不可接受。**

## 4. 结论

| 项 | 状态 |
|---|---|
| 给 `0x18`/`0x60` 计 per-tile 代价 | ❌ **否掉**（系数非物理 + 恶化已准模型） |
| 缺失的第三个分量 | ❌ **不是「非卷积 tile 的计数项」** |
| 时序模型适用区间 | 仍为**地板主导**（regnet −0.2% / shufflenet +9.5% / densenet −13.4%） |

**⇒ 第三个分量不是简单的计数项。** 它更可能是**结构性的**
（例如 `shufflenet` 的 tile 虽多但每个都很小、`googlenet` 的 Concat 造成依赖停顿），
**不是一个可以乘出来的单价。**

## 5. 下一步（按上轮承诺转向实证）

上轮我承诺：「如果不能，我会把三个分量的边界写清楚，然后**用现有模型先做一次离线实验**」。
**现在兑现：下一轮用现有（地板主导区间可靠的）时序模型做「去冗余拷贝」的收益估算。**

依据来自 docs/47/50（已实测）：
* 同一条 `src→dst` 的 1×1×32 拷贝执行 **81 遍（3 核）/ 54（2 核）/ 46（1 核）** = `27 ops × cores`
* 纯拷贝提交占 **8.3%（3 核）/ 11.2%（2 核）** 的推理硬件时间
* 完整签名重复 19.9%，最大一组就是这 81 遍

**⇒ 这是唯一有实测量级的「无损」优化路径，而且它的收益可以直接用时序模型算。**

## 6. 教训（本轮新增）

1. **★★ 系数非物理 ⇒ 模型形式错了，不是数据不够。**
   `0x18` 的负系数一眼就能判断不可能 —— **如果我只看「平均误差改善了」就会采纳这个修正**。
   **必须检查每个参数的物理意义，而不只看拟合优度。**
2. **★ 修正不能牺牲已经准的部分。** `shufflenet` 从 +9.5% 到 +65.4% 是**不可接受的代价**，
   哪怕整体平均误差变小了。**评估修正时要看「最差的那个」是否变差。**
3. **★ 连续两次修正失败（docs/78 的 scale、本轮的 tile 单价）⇒ 该换问题而不是继续修。**
   两个修正都是「加一个线性项」，都失败了 ⇒ **缺失的分量可能本质上是非线性/结构性的**，
   继续在「加项」这个方向上试下去收益很低。
