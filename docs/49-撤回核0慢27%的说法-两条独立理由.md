# 49 · 撤回 docs/41 的「核 0 比核 1/2 慢 27%」（两条独立理由）

> 本轮（第 10 轮）顺手去验证 docs/41 §5.2 给的一条**可操作建议**：
> 「核 0 比核 1/2 慢 27% ⇒ 调度优先避开核 0」。
> 结果：**在 yolov5s 上不成立（方向还相反），而且这个杠杆根本不可用。**
> 两条独立理由都成立，所以这条建议**撤回**。

---

## 1. 理由一：换一个负载，效应不成立（方向相反）

`docs/41` 的结论来自 **RKLLM 的 3-task 小提交**（`hw` 中位 77.3 / 61.0 / 60.7 µs，
`core_mask ∈ {1,2,4}`）。本轮用**同一个模型、同一种探针**在 **yolov5s** 上重做：

```
每配置 16 趟（4 预热 + 12 测量），只挂 submit_timer（低开销，docs/43）

cm=1（核 0）: Σhw = 246.561 ms / 16 = **15.410 ms/趟**
cm=2（核 1）: Σhw = 253.328 ms / 16 = **15.833 ms/趟**
cm=4（核 2）: Σhw = 253.263 ms / 16 = **15.829 ms/趟**
```

⇒ **核 0 反而比核 1/2 快 2.7%**（15.410 vs 15.833/15.829），不是慢 27%。

**两个负载给出相反的符号。** 这说明「核 0 有额外开销」**不是一个硬件常数**，
最多是一个与负载相关的现象（LLM 的 3-task 权重密集型小提交 vs yolov5s 的大提交）。
**一个在 A 负载上测到 27% 的效应，在 B 负载上符号都反了 —— 这种结论不能作为调度依据。**

（顺带说明：本轮没有去重做 LLM 的对照，所以**不能说 LLM 那个 27% 是假的**，
只能说它**不可推广**。）

---

## 2. 理由二：这个杠杆**根本不可用**

更根本的一条：即使「避开核 0」是真的，**运行时也不允许**。
`init_runtime(core_mask=...)` 只接受**预定义组合**：

| `core_mask` | 含义 | 结果 |
|---|---|---|
| `1` | 核 0 | ✅ |
| `2` | 核 1 | ✅ |
| `4` | 核 2 | ✅ |
| `3` | 核 0+1 | ✅ |
| `7` | 核 0+1+2 | ✅ |
| `5` | 核 0+2 | **`INIT_FAIL ret=-1`** |
| `6` | 核 1+2 | **`INIT_FAIL ret=-1`** |

⇒ **不存在「只用核 1+2」或「只用核 0+2」的合法配置。**
所有多核配置都**必须包含核 0**。所以「调度优先避开核 0」在支持的 API 下**无法实施**。

---

## 3. 修正后的说法

> **「核 0 比核 1/2 慢」是一个负载相关的观察，不可推广；且运行时不允许排除核 0，
> 所以它不构成一条可实施的调度建议。**

docs/41 §5.2 与 README 里相应的表述已改。

**同时保留的（仍然成立的部分）**：那个 27% 是**实测**的（1352×3 交错样本，LLM 负载），
只是**不可推广**。它不是错误数据，是**错误的一般化**。

---

## 4. 本轮还确认的两件事

1. **支持的 `core_mask` 只有 5 个**（1/2/4/3/7）。这本身是有用的接口事实：
   任何「自定义核组合」的设想都走不通，**要么全用、要么按预定义组合用**。
2. **低开销探针下 yolov5s 单核 = 15.410 ms/趟**（`hw`），与 docs/43 的 15.405 ms 一致
   —— 这是第三次独立复现同一个数（另两次见 docs/43/44）。

---

## 5. 教训（本轮新增）

1. **★ 换一个负载去验证，是最便宜、最有效的证伪手段。** 这条结论在文档里躺了五轮
   （docs/41→48），一直没人用第二个负载撞过。**只要换负载跑一次就翻案了。**
   代价是三次 16 趟的推理 —— 不到一分钟。
   ⇒ **凡是「某单元比另一单元慢 X%」这类结论，必须至少两个负载。**
2. **★ 可操作性要单独验。** 即使效应成立，也可能**没有 API 能利用它**。
   本轮 `init_runtime(5/6)` 直接返回 `-1` —— 一条建议在写下来之前，
   **应该先确认「用哪个接口去实施」**。写不出接口的建议不该进「优化杠杆」表。
3. **★ 「错误的一般化」比「错误的数据」更隐蔽。** 27% 那个数是真的（1352×3 样本），
   我在文档里也是如实记的；错的只是**从 LLM 负载外推到「核 0 天生慢」**。
   **数据和结论要分开审计** —— 数据没问题不等于结论没问题。
4. **撤回要写在正文里，不能只改 README。** 这一条我做了横幅 + 表格修正，
   因为「避开核 0」曾经出现在优化杠杆表里，是**会被照着做的**那一类结论。
