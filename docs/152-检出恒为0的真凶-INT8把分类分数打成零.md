# docs/152 — ★ 找到「检出恒为 0」的真凶：INT8 把分类分数整支打成了零

> 之前所有测试里 YOLO 的检出数都是 **0**，我们一直归因为"标定用随机噪声"。
> 拿到真实 COCO 数据重标之后仍然是 0 —— 这才查出根本不是标定的问题，
> **是 INT8 量化把分类分支整支压成了 0**。

---

## 0. 结论

| 模型 | 框(max) | 分数(max) | 分数非零数 | 可用? |
|---|---|---|---|---|
| FP16（不量化） | 643.0 | **0.9268** | 10331 | ✅ |
| INT8（原模型，单输出） | 642.5 | **0.0000** | **0** | ❌ |
| INT8（**拆成双输出**） | — | **0.8920** | 1060 | ✅ |

**根因**：模型的最后一个 `Concat` 把 **框坐标（0~640）** 和 **类别分数（0~1）** 拼进**同一个输出张量**。
INT8 量化给这个输出只算了一个 scale —— 在 0~640 的量程下，0~1 的分数全部量化成 0。

**修复**：在 `Concat` 之前把模型切开，输出两个独立张量（框 logits 64 通道 + 分类分数 80 通道），
`Concat` 及 DFL 尾部在 CPU 用 numpy 完成。

修复后**精度可用且速度更快**：

| | 耗时 | 相对 |
|---|---|---|
| 原 INT8（坏的） | 32.08 ms | — |
| **修复版（head + CPU 尾部）** | **30.42 ms** | **+5.5%** |
| └ head 推理 | 27.82 ms | |
| └ CPU 尾部（只算候选锚点） | 2.60 ms | |

## 2. 怎么发现的

### 2.1 真实标定后依然是 0

用 27 张真实图重标，再和 ONNX FP32 逐张比：

```
整体 cosine : 中位 0.999148
box  cosine : 中位 0.999148   ← 框完美
cls  cosine : 中位 0.000000   ← 分数余弦恒 0（=全零）
检出数: ONNX 1866 / RKNN 0
```

**整体 cosine 0.999 是假象**：输出张量里框的数值是 0~640，分数是 0~1，
前者在向量范数里占绝对主导，把后者的崩塌完全掩盖了。
**必须按行分开算 cosine 才能看出来。**

### 2.2 二分定位

| 实验 | 结果 |
|---|---|
| 同模型改 `do_quantization=False`（FP16） | 分数 max **0.9268**，非零 10331 → **模型本身没问题** |
| INT8 原模型 | 分数全 0 → **问题出在量化** |
| INT8 + 拆成双输出 | 分数 max **0.8920**，非零 1060 → **修好了** |

⇒ 不是标定数据的问题，不是模型的问题，是**量化时输出张量的量程被框张量带偏**。

| 指标 | 值 |
|---|---|

| 同类且位置 <5px 匹配 | **1792 = 96.0%** |

**96% 的检出与 FP32 一致**，可以认为这个 INT8 模型是可用的。
（cls cosine 最低那张 0.568 需要单独看，可能是低光照图。）

## 4. 影响面：这是 YOLOv8/v11 上 RKNN 的通病

`Concat` 合并 `[box, cls]` 是 **Ultralytics 导出 ONNX 的默认行为**
（`Detect.forward` 里 `torch.cat([dbox, cls], dim=1)`）。

⇒ 任何直接用 RKNN 转 YOLOv8/YOLO11 官方 ONNX 的部署，**都可能踩这个坑**，
而且症状极具欺骗性：

- 推理不报错
- 输出形状完全正确 `(1,84,8400)`
- 框坐标看着挺合理
- **只有分数是 0**，于是 NMS 之后检出恒为 0

我们前面 `docs/144`~`docs/151` 那一堆"检出 0 个"全是这个原因，不是标定、不是分块、不是量化精度不够。

**判别方法**（一条就够）：

```python
o = rknn_out[0]          # (84, 8400) 或 (1,84,8400)
print(o[:4].max(), o[4:].max())    # 框应有几百，分数应在 0~1
# 若分数恒 0 ⇒ 中招
```

## 5. 修复做法（可复用）

```python
# 1) 在最终 Concat 之前切开模型，输出两个张量
import onnx
onnx.utils.extract_model("yolo11n_640.onnx", "yolo11n_640_head.onnx",
                         ["images"],
                         ["/model.23/Concat_output_0",     # 框 logits (1,64,8400)
                          "/model.23/Sigmoid_output_0"])   # 分类分数 (1,80,8400)

# 2) 正常 INT8 量化 —— 两个输出各自算 scale，互不干扰
r.config(target_platform="rk3588", mean_values=[[0,0,0]], std_values=[[255,255,255]],
         quantized_dtype="w8a8", optimization_level=3)
r.load_onnx(model="yolo11n_640_head.onnx")
r.build(do_quantization=True, dataset="dataset640.txt")

# 3) CPU 侧补 DFL：只对 score>conf 的候选锚点算，2.6 ms
```

DFL 的 numpy 实现（与 ONNX 对齐到相对误差 2.9e-7）：

```python
p  = logits.reshape(1,4,16,N).transpose(0,3,1,2)
e  = np.exp(p - p.max(-1, keepdims=True)); pr = e / e.sum(-1, keepdims=True)
d  = (pr.transpose(0,3,2,1) * np.arange(16, dtype=np.float32).reshape(1,16,1,1)).sum(1)
x1 = anchor - d[:,0:2]; x2 = anchor + d[:,2:4]
box = np.concatenate([(x1+x2)*0.5, x2-x1], 1) * stride
out = np.concatenate([box, cls], 1)        # 最终 (1,84,8400)
```

`anchor` / `stride` 两个常量直接从 ONNX 的 `Constant_12` / `Constant_15` 节点取出，存成 `.npy`。
