# 74 · ⚠️ `GlobalAveragePool` 被编译成 **7×7 平均池化** —— probe4 是个坏测试用例

> 接 [docs/73](73-三方对照与剩余差距归因.md)（把 6.09 的差归因到「激活量化」）。
> 本轮实现激活量化后**没对上**（算得 2.9，官方是 177.28）。
> 排查发现原因不在量化，而在 **`GlobalAveragePool` 的编译语义**，并**部分推翻 docs/73 的归因**。

---

## 1. 排查：问题出在 GAP，不在量化

我按 `.cfg` 的 per-tensor 参数实现了标准量化路径（int8 卷积 + requant + Relu + GAP + Gemm），
结果 **2.9062**，与官方的 177.2787 差 174。

**关键线索**：`.cfg` 里 GAP 输出的 scale 是 **1.2743**，而 conv 输出 `c` 的 scale 是 **1.0872**
—— **两者量级相同**。

**如果 GAP 真是「1024 个像素求平均」，输出幅值会掉 1024 倍，scale 应该小得多。**
scale 量级相同 ⇒ **它没有在 1024 个像素上求平均。**

---

## 2. ★ 真正的原因：`GlobalAveragePool` → **7×7 平均池化**

docs/63 早就记过一条，我当时只当成「算子形态」没深究：

```
probe2/probe3 的寄存器: op2  kw=7 kh=7  kernels=1  ch_align=16  WEIGHT_SIZE1=784=7·7·16
```

**`kernels=1`（depthwise 通路）+ 7×7 窗口 ⇒ 这就是一个 7×7 平均池化。**

而我的 probe4 的特征图是 **32×32**。**7×7 池化 ≠ 全局平均**（只在输入恰好 7×7 时才等价）。

**⇒ RKNN 编译出来的模型，与我喂给它的 ONNX 在语义上不同。**
`.cfg` 里那个 `gap_2conv0` 的名字也印证了这一点：它是「conv0」——
**编译器把 `GlobalAveragePool` 换成了一个卷积**。

---

## 3. ⚠️ 这**部分推翻** docs/73 的归因

docs/73 里我说：

```
官方模拟器 vs 浮点 = 4.687 > 权重量化误差 1.43  ⇒ 差的是激活量化
```

**现在看，这 4.687 里至少有一部分来自「GAP 被换成 7×7 池化」的语义差异，不全是激活量化。**
两个因素混在一起，我当时只归因了一个。

**⇒ docs/73 的结论要收窄为**：
「官方模拟器与浮点的差 **超过**权重量化误差 ⇒ 还有别的因素；
候选有 ① 激活量化 ② 算子替换（已证实 GAP→7×7 池化）。**两者都还没有分离测量。**」

---

## 4. 教训

1. **★★ 我把「算子被替换」当成了「算子形态」，漏了它改变语义。**
   docs/63 记下 `kw=kh=7, kernels=1` 时，我写的是「池化走 depthwise 通路」——
   **那是形态描述，不是语义描述**。真正的含义是「**全局**平均变成了**局部 7×7** 平均」。
   **记录一个现象时，要写清它「改变了什么语义」，而不只是「长什么样」。**
2. **★ 探针要选「编译器不会改写语义」的模型。** probe4 用了 `GlobalAveragePool`，
   而它在 32×32 输入上被编译成 7×7 池化 ⇒ **这个模型不适合验证数值**。
   **做数值验证的探针要避开会被编译器改写的算子**（或让它落在等价条件下）。
3. **★ 数值对不上时，先查「模型是不是同一个」，再查「实现对不对」。**
   我一开始怀疑自己的量化公式（差点去调 scale），
   但「scale 量级相同」这条线索直接指向了算子语义。
   **先排除「输入不同」，再排查「算错」。**
4. **★ 归因到单一原因时要警惕。** docs/73 我把 4.687 全归给激活量化，
   现在看至少是两个因素。**差值大时，先假设有多个因素，再逐个分离。**
