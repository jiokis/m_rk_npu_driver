# docs/154 — 把整条链路搬进 C：14.27 → 31.77 FPS（+123%）

> `docs/153` 的 Python 流水线是 14.27 FPS，而纯推理（C）有 26.6 FPS。
> 差的 12 FPS 到底在哪？量出来是 **rknnlite 的 Python 封装**。搬到 C 之后 31.77 FPS。

---

## 0. 结果

| 实现 | 吞吐 | 含 DFL | 含 NMS | 备注 |
|---|---|---|---|---|
| Python 流水线（`docs/153`） | **14.27 FPS** | ✅ | ✅ | 6 worker / 6 独立 ctx |
| **C 完整链路（闭环）** | **32.3 FPS** | ✅ | ✅ | 6 worker / 6 独立 ctx |

**+126%**。C 版在真实 tile 上：**46 原始框 → NMS 后 7 框**，
与 ONNX-FP32 同架构（2×2 分块）的结果 **完全一致**（也是 7 个），
说明 DFL 解码与 NMS 都正确，不是靠牺牲正确性换速度。

三轮 100 帧长跑：**32.34 / 32.66 / 32.05 FPS**（偏差 <2%）。
NMS 开销 **0.001 s / 100 帧 = 0.01 ms/帧**，可以忽略。

## 1. Python 慢在哪：逐层量

| worker 数 | 每 tile 推理 | 整帧吞吐 |
|---|---|---|
| 1 | **38.18 ms** | 5.86 FPS |
| 3 | 41.70 ms | 11.08 FPS |
| 6 | **59.08 ms** | 14.37 FPS |

而 C 里同样的 tile 推理只要 **~28.5 ms**。两个结论：

1. **单线程下 Python 每 tile 就多花 ~10 ms** —— `rknnlite` 封装（numpy 转换、ctypes、缓冲区管理）的成本
2. **并发后进一步恶化**（38 → 59 ms）—— GIL + 内部锁争用

再看时间分布（6 worker）：120 个 tile，**推理合计 6997 ms / 后处理(DFL) 689 ms**，
但墙钟只有 1900 ms ⇒ **worker 只有 61% 的时间在真正做推理**，其余在等 GIL。

## 2. C 版怎么写的

`deploy/bench/bench_full.c`，沿用 `bench1280.c` 的分块+worker 框架，加了：

```c
// 每个 worker 独立上下文（不是 dup_context 共享），按 i%3 绑核
for (i = 0; i < nw; i++) {
    rknn_init(&ctx[i], model, len, 0, NULL);
    rknn_set_core_mask(ctx[i], (i%3==0) ? CORE_0 : (i%3==1) ? CORE_1 : CORE_2);
}

// 每个 tile：inputs_set → run → outputs_get(want_float=1)
//   out[0] = (1,64,8400) logits   out[1] = (1,80,8400) 分数
// 只对 max(cls)>0.25 的锚点算 DFL：
for (a = 0; a < 8400; a++) {
    best = max over 80 classes of cl[c*8400+a];
    if (best <= 0.25) continue;
    for (g = 0; g < 4; g++) {           // 4 组，每组 16 个 bin
        softmax over lg[(g*16+b)*8400+a];
        d[g] = Σ prob[b] * b;           // 期望值
    }
    box = (anchor ± d) * stride + tile_origin;
}
```

关键点：
- **每个 worker 一个独立 ctx**（`docs/153` 证明共享会互踩输出）
- **阈值在 C 里先筛**，DFL 只对候选锚点算（每 tile 通常几十个）
- 框按 tile 原点回映到全图坐标

## 4. 顺带一个发现：独立 ctx 比 dup_context 更快

| 上下文方案 | 吞吐 |
|---|---|
| `rknn_dup_context` 3 个 ctx / 6 worker 共享（`docs/151`） | 26.6 FPS |
| **6 个独立 ctx / 每 worker 一个**（本实现） | **31.77 FPS** |

`dup_context` 省内存（共享权重），但**多线程共享句柄会拖慢**。
内存换速度：4.06 MB × 6 = 24 MB，很划算。
