# 量化自由度实验：不依赖硬件逆向的优化空间

> 代码：[src/quant/quant_experiment.py](../src/quant/quant_experiment.py) ·
> 原始结果：[src/quant/quant_results.json](../src/quant/quant_results.json)
> 依据：[07-战略转向](07-战略转向.md) 判定「量化自由度」是性价比最高的空白 ——
> **纯软件、收益可量化、不依赖硬件 RE**。

---

## 一、为什么盯量化

硬件的量化能力其实很强（int4/int8/int16/fp16/bf16/tf32），但官方工具链只给到 w8a8，
而且 **w4a16 在 RK3588 上被直接拒绝**（我们早先实测的原始报错：
`ERROR: target_platform: rk3588 not support quantized_dtype: w4a16!`）。

于是 int4 用不上 —— **但卡住它的不是硬件，是量化方法本身**。

## 二、v1 实验的两个错误（保留记录）

第一版跑完得出了"Hadamard 旋转让 int4 更差"的结论。**那个结论是错的，错在实验设计**：

| 错误 | 具体表现 | 后果 |
|---|---|---|
| **离群轴搞错** | 权重离群加在**行**（输入维度），却用 `axis=0` 做 per-channel（得到的是**列** scale） | 列 scale 管不到行离群 → int4 权重误差虚高到 98.7% |
| **指标会骗人** | 只看全局相对误差 `‖Yq−Y‖/‖Y‖` | 巨量通道是最大值、被量化得相对精确，且它们主导 `‖Y‖`；于是「99% 的值变成 0」这种灾难**在指标上几乎看不出来** |

**教训**：量化实验必须直接看**张量级**指标（尤其零值占比），不能只看输出误差。

## 三、v2 结果

数据：`W(512,512)` 含 8/512 行离群 ×10 · `X(128,512)` 含 4/512 通道巨量 ×100
（模拟 LLM 的 massive activations）。指标：相对误差 / **零值占比** / 原始峰均比。

### 3.1 int4 的致命失效：值被大量压成 0

| 方案 | 相对误差 | **零值占比** |
|---|---|---|
| `X` per-tensor | 16.61% | **99.35%** ← 几乎全废 |
| `X` per-token（行） | 12.91% | **99.28%** |
| `X` per-通道（列） | 10.93% | 15.82% |
| `W` per-tensor | 64.47% | **98.53%** |
| `W` per-输出通道（列） | 14.15% | 18.37% |
| `W` per-输入通道（行） | 43.84% | 74.06% |
| `W` per-group(g128, 沿 N) | 62.93% | 97.31% |

**两个反直觉之处：**

1. **per-token 救不了 int4 激活**（零值占比仍 99.28%）。per-token 只解决"不同 token 幅度不同"，
   而这里的病根是"同一 token 内不同通道幅度差 100 倍"——那是 per-channel 才能治的。
2. **per-group 并非总是更好**（97.31%，比 per-输出通道差得多）。
   分组必须**沿着离群所在的轴**分；我的离群在输入轴，而分组分在输出轴 N 上，
   等于把不该切的切了。**"per-group 优于 per-channel"是有前提的，不是普适结论。**

### 3.2 Hadamard 旋转：直接消灭失效模式

对正交矩阵 `R` 有 `XW = (XR)(RᵀW)`，两侧同时旋转，结果不变（实测等价性偏差 `0.000029%`）。

| 方案（int4） | 相对误差 | **零值占比** | 峰均比 |
|---|---|---|---|
| `X` per-tensor（未旋转） | 16.61% | **99.35%** | 34.0 |
| `X` per-tensor（**旋转后**） | 15.61% | **21.48%** | **6.2** |
| `X` per-token（未旋转） | 12.91% | 99.28% | 34.0 |
| `X` per-token（**旋转后**） | **8.03%** | **9.66%** | 6.2 |

int8 下效果更明显：`X` per-tensor 零值占比 **73.81% → 1.21%**，相对误差 **7.52% → 0.86%**。

旋转把峰均比从 **34.0 压到 6.2** —— 这就是它起作用的机制：**把少数通道的离群能量均摊到所有通道上**。
Hadamard 矩阵只有加减法，硬件实现几乎零成本。

### 3.3 ⚠️ 但输出指标给出了相反的信号

| 方案 | 输出相对误差 | 余弦相似度 |
|---|---|---|
| `X` int4 per-tensor | 21.48% | 0.976964 |
| `X` **旋转** int4 per-tensor | **24.08%**（更差） | 0.972213 |

**旋转让张量级质量大幅改善（零值 99.35% → 21.48%），却让全局输出误差变差。**

这不是矛盾，是**指标选择问题**：未旋转时，巨量通道被精确保留（它们是 scale 的来源），
而其它 99% 的值全归零——但那些零值对 `‖Y‖` 贡献很小，所以全局指标看着还行。
旋转后，所有通道都被"中等精度"地保留，误差均匀分摊到 512 个通道上，总量反而更大。

**结论：全局 Frobenius 误差不是 int4 质量的可靠代理。**
要判断旋转到底有没有用，必须用**真实模型 + 下游任务指标**（困惑度 / 准确率）。

## 四、可落地的组合（有数据支撑的部分）

| 做法 | 数据支撑 | 成本 |
|---|---|---|
| **权重 per-输出通道**（不要 per-tensor，也别沿错轴分组） | int4 零值 98.53% → 18.37% | 纯离线，零运行时开销 |
| **激活先做 Hadamard 旋转再 per-tensor** | int4 零值 99.35% → 21.48%，峰均比 34→6.2 | 一次正交变换，只有加减法 |
| **分组要沿离群轴** | 沿错轴时 97.31% vs 沿对轴 18.37% | 需先做离群分析 |

> 「旋转后 int4 能否真正提升下游精度」**尚未验证** —— 需要真实模型。
> 这是下一步要补的实验，不能拿当前的合成数据下结论。

## 五、局限（必须说清楚）

1. **合成数据**：分布是人为构造的，真实 LLM 的离群结构更复杂（层间差异、随 token 变化）
2. **没有下游任务**：只测了张量与输出误差，没测困惑度
3. **单层**：只模拟了一次 `X @ W`，没有误差在网络中的累积
4. **对称量化**：没测非对称零点、NF4、随机舍入、importance matrix
5. **硬件未验证**：本实验是纯数值研究，**没有在 NPU 上跑过**。硬件的 int4 通路是否
   如预期、out-cvt 片上 requant 能否直接出 int8，都还需要上板验证
