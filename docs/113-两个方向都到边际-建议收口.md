# 113 · 两个方向都到边际 —— 建议**收口**

> 接 [docs/112](112-成本收益判断-切分驱动该不该继续.md)（建议停切分驱动、转 A+B）。
> 本轮实际试了 A 与 B，**两条都到边际。**

---

## 1. 方向 B（用 `NC1HWC2` 解布局）：**被卡住，但不是因为布局**

尝试：在 monkeypatch 的 wrapper 里读 IR 节点的 `layout` 属性。

```
IR 节点的属性：['kernel_shape','pads','strides','dilations'] / ['c_type'] / []
ir.node[0] 是**普通 protobuf NodeProto**（dir 里全是 protobuf 方法）
```

**⇒ 原因明确**：`layout` 由 **`RKNNLayoutMatchPass`（第 20 步）** 添加，
而**可 hook 的 Python 规则在第 19 步（`RKNNTilingPass`）及之前触发** ⇒ **看不到 layout。**

**⇒ 不是「布局不可得」，而是「我 hook 的位置太早」。**
（要看 layout 得 hook 第 20 步之后，而那里没有 Python 回调可拦。）

## 2. 方向 A（用编译器 `Cycles` 改进时序模型）：**效果有限**

```
模型              编译ms   地板ms   实测ms
resnet18          2.662   1.542   1.866
squeezenet1_0     2.769   2.904   3.123
googlenet         1.050   2.482   5.977
regnet_x_400mf    1.861   6.588   7.692
efficientnet_b0   4.045   5.412   9.294

两参数最小二乘：t = 0.235×编译 + 1.297×地板
```

**⇒ 误差 ±14~42%，系数也不物理**（0.235 倍编译周期没有解释）。

**⇒ 编译器自己的 `Cycles` 数据**不能**直接改进我的时序模型。**
（唯一有价值的一条仍是 docs/104 的 `max(编译周期, 地板)`：把 `regnet` 从 −75.8% 收到 −14.4%。）

## 4. ★ 建议：收口

### 已确认的成果（6 项，可直接引用）

1. **融合规则**：`Conv→Relu` / `BN→Relu` / `Constant→Clip` / `Add→Relu` 四种对 100% 可融合，其余 0%
2. **规则表**：`fuse_rules` 355 / `convert_rules` 206 / `hardware_rules` 12（可导出、可 hook）
3. **流水线**：33 个 pass 的名字与顺序
4. **IR 格式**：`NC1HWC2`，`C2 = 16`
5. **编译器自己的性能模型**：`Cycles(DDR/NPU/Total)` + `RW(KB)`
6. **编译器估算与我的模型失败方式相同** ⇒ 缺失分量在「算子之间」

### 已交付的优化结论（3 项）

* 合并提交 **12.83 ms**（多核实测靶子）
* 去冗余拷贝 **2.11 ms**（正确性已验证）
* 参数化曲线：减 25/50/75% → 9.07 / 18.13 / 27.20 ms

### 明确边界（4 项）

* 任意 `out_ch` 的通用权重布局：**未得**（但原因已改为「hook 位置」，不再是「不可得」）
* 提交数驱动：**未得**（5 粒度 + 2 通道全否）
* 激活量化：未实现（缺口 6.09）
* 时序模型第三分量：未找到

## 5. 教训（本轮新增）

1. **★★★ 「hook 位置太早」和「不可得」是两回事 —— 我差点把前者写成后者。**
   方向 B 失败时，我第一反应是「docs/79 的结论成立（不可得）」；
   **但真正的原因是 layout 在第 20 步才加，而我拦的规则在第 19 步。**
   **失败时要问「是对象不存在，还是我观测的时机/位置不对」。**
2. **★★ 一个方向「能开始」不等于「能完成」。** 方向 A 有现成的 `Cycles` 数据，
   看起来一定能改进模型；**实测拟合 ±14~42%** ⇒ **数据可用 ≠ 数据有用。**
3. **★ 两条路都到边际时，收口是正确决定而不是放弃。**
   我已投入 ~33 轮在两大未解问题上，**拿到 6 项确认成果 + 3 项交付结论**。
   **继续投入的期望收益已经低于「整理与交接」的价值。**
