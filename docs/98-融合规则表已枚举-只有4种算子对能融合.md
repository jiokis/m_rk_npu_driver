## 2. ★ 三条直接解释

### ① `Conv→Sigmoid` = 0% ⇒ **解释了 `efficientnet_b0` 的 0 可融合对**

`efficientnet` 用的是 **SiLU/Swish**（`Sigmoid` + `Mul`），而 **`Conv→Sigmoid` 不融合**、
**`Sigmoid→Mul` 也不融合** ⇒ 它的 239 个节点里**没有一对可融合** ⇒ **88 次提交的碎片化。**

**⇒ 这是 `efficientnet_b0` 碎片化的直接、可读的原因**（不是猜的）。

### ② `Conv→Concat` = 0%、`Conv→Add` = 0% ⇒ **解释了 Concat/残差模型的碎片化**

`densenet121`（62 个 Concat）、`regnet`（22 个 Add）、`resnet18`（Add）
—— 这些算子**打断融合**。

### ③ `Conv→Conv` = 0% ⇒ **相邻卷积在 IR 层不融合**

**⇒ 说明「融合」是两层：**
* **IR 层**（`can_fuse`）：只做「激活并入前算子」
* **tiling 层**（`hardware_rules`）：把连续的卷积链切成 tile —— **这才是提交打包的地方**

**⇒ 这与 docs/97 的判断一致（两层机制），现在有了具体证据。**

## 4. 教训（本轮新增）

1. **★★★ 「枚举」比「探针」快一个数量级。** 20 轮探针 + 否证 → 3 条不完整的规则；
   **一轮枚举 → 4 条 100%/0% 的规则，覆盖 9 个模型。**
   **当被研究对象是一个「判定函数」时，枚举它的输入空间，而不是设计实验去反推。**
2. **★★ 读到的规则能**修正**推断出的机制。** 探针对 SE 的机制推测是「全局同步点」；
   实际是 **`Conv→Sigmoid` 不融合**。**机制细节只有读代码才能得到。**
3. **★ 100%/0% 这种干净的分布是「找到规则」的标志。**
   如果枚举结果是一堆中间比例，那说明还没找对分类维度。
   **看到全 100% 或全 0%，基本可以确认规则的形式。**
