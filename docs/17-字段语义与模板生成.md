## 一、方法论：怎么在**没有硬件手册**的情况下定字段语义

可用的武器只有三样：**取值分布**、**跨算子结构关系**、**外部参考模型**。
本轮主要靠前两样 —— **自证**，不依赖任何文档。

### 1.1 突破口：发现「维度 − 1」约定

盯着 `CORE 0x3014` 的取值看，出现了这样两列：

```
0x3014 低16 :  319, 319, 159, 159, …, 79, …, 39, …, 19
0x3018      :   31,  31,  63, …, 127, …, 255, …, 511
```

**319 = 320−1，159 = 160−1，79 = 80−1，39 = 40−1，19 = 20−1**
**31 = 32−1，63 = 64−1，127 = 128−1，255 = 256−1，511 = 512−1**

左边是 **yolov5s 经典的降采样序列**（640→320→160→80→40→20），
右边是 **yolov5s 经典的通道序列**（32→64→128→256→512）。

**⇒ 硬件存的是「维度 − 1」（最大索引），不是计数。**

### 1.2 然后系统性搜出所有尺寸字段

有了这个约定，就能反过来搜：**哪些寄存器的取值集合落在这个家族里？**

```
DPU      0x4030  ← {319,159,79,39,19}
DPU_RDMA 0x500c  ← {319,159,79,39,19}
CORE     0x3018  ← {31,63,127,255,511}
DPU      0x4058  ← {511,255,127,63,31,15}
DPU_RDMA 0x5014  ← {511,255,127,63,31,15}
PPU      0x6014 / 0x6020 / PPU_RDMA 0x7014  ← {255,31}
```

**呈现出一个非常整齐的结构：每个流水级都有自己的一对 (尺寸, 通道)。**

### 1.3 用「跨寄存器关系」进一步定语义

`CNA 0x107c` 的取值是 **[1280, 640, 320, 160, 80]** —— 逐级减半。
而与 `0x1080` 做比值，在 22 个算子上恒为：

```
0x1080 / 0x107c = 639, 79, 39, 19, 9      ← 全是「高 − 1」的形态
```

例如 op1：`408960 / 640 = 639` —— 严格整数。

**⇒ `0x107c` = 行跨距，`0x1080` = 行跨距 × (高−1)。**

> 这条关系**可证伪且全部通过**（22/22），比"看着像"强得多。

## 二、已自证的字段（12 个）

| block | 寄存器 | 名称 | 置信 | 依据 |
|---|---|---|---|---|
| CNA | `0x1070` | 特征/输入张量地址 | **确证** | 值精确落在 MEM_CREATE 的 dma_addr 缓冲区 |
| CNA | `0x1110` | 权重张量地址 | **确证** | 同上 |
| CNA | `0x107c` | 行跨距 | 强 | 取值 = 特征图宽的 2 倍，逐级减半 |
| CNA | `0x1080` | 行跨距 × (高−1) | 强 | 22/22 算子比值恒为 高−1 |
| CORE | `0x3014` 低16 | 输出宽 − 1 | **确证** | 与 yolov5s 降采样序列完全一致 |
| CORE | `0x3018` | 输出通道 − 1 | **确证** | 与 yolov5s 通道序列完全一致 |
| DPU | `0x4030` | 尺寸 − 1 | 强 | 同宽家族 |
| DPU | `0x4058` | 通道 − 1 | 强 | 同通道家族 |
| DPU_RDMA | `0x500c` | 尺寸 − 1 | 强 | 同上 |
| DPU_RDMA | `0x5014` | 通道 − 1 | 强 | 同上 |
| PPU | `0x6014` | 通道 − 1 | 推测 | 仅 2 个取值 |
| PPU_RDMA | `0x7014` | 通道 − 1 | 推测 | 仅 2 个取值 |

**置信度是分级标注的**：`确证`（有独立证据链）> `强`（跨样本一致的结构关系）> `推测`（样本太少）。

## 三、★ 模板生成器（本轮的可实用产出）

有了"地址字段确证"这一条，就能做一件**能安全落地**的事：

> **拿一个真实算子当模板，只替换已确证的地址字段，重新生成命令流。**

为什么只换地址 —— 地址语义是**确证**的；形状/步长只到"强/推测"，
贸然改动可能造出无效配置。**这是"能安全做的最小可用生成器"。**

### 实测

```
$ python3 -m rknpu.cli retarget 24
  源: 10 段 · op3 · 404 条指令
  替换: CNA 0x1070 → 0x30000000
  替换: CNA 0x1110 → 0x40000000
  生成: 10 段 · 424 条指令
  链完整: 10/10
  地址替换: ✅ 生效
```

（424 = 404 条体 + 10 段 × 2 条链，数目自洽）

生成物**通过模拟器执行**，链完整，地址替换生效。

### 能力边界（必须说清）

| 能做 | 不能做 |
|---|---|
| 把已有算子**改地址**复用 | 从零描述一个**新形状**的算子 |
| 生成正确的链结构 | 生成新的形状/步长/量化字段 |
| 在模拟器里验证结构 | 保证在**真硬件**上能跑（未上板验证） |

## 四、一个语料层面的限制（诚实标注）

**yolov5s 是 640×640 方输入，所有特征图都是方的。**
所以「宽−1」与「高−1」的数值**完全相同**，我**无法区分哪个字段是宽、哪个是高**。

`0x3014` 低16 是宽−1 已由序列证明；高16 是**另一个字段**（取值 16/208/96 等，
与宽无简单关系），尚未定性。

**解法**（需要硬件但零风险）：用**非方形输入**的模型跑一次再抓，
宽高字段会给出不同数值，一比即知。当前板载模型都是方形输入，需另找一个。
