## 0. 提交预算表：把一次推理的 hw 时间拆成四账

```
PEAK  = 1.024 T-MAC/s/核（阵列 32×32 × 1.0 GHz，docs/44）
FLOOR = 67.4 µs/提交（144 个零算术量提交的实测中位，docs/43）

配置        提交   轮  tile   算术(ms)  地板(ms)  搬运KB  实测(ms)  残差(ms) 占比   预测(FLOOR=67.4)  误差
cm=7 3 核    77  145   428    2.686    6.160   10.9    8.461   −0.385  −4.5%      7.876 ms    −6.9%
cm=3 2 核    77  208   413    4.029    6.160    7.4   13.501    3.312  24.5%      9.219 ms   −31.7%
cm=1 1 核     4  615   615   14.504    0.320   12.2   15.419    0.594   3.9%     14.774 ms    −4.2%
```

**读法**：三核那趟的 hw 里，**地板 6.16 ms + 算术 2.69 ms**，地板是算术的 **2.3 倍**。
这就是「瓶颈是提交/轮粒度，不是乘法器」在账面上的样子。

## 1. ★ 结掉一个我自己列的待办：搬运通路**不需要**单独的带宽项

上一轮（docs/51 §4 未结项 #6）我写：「PPU 搬运的字节量尚未进模型」。
本轮量了一下，**这个待办是多余的**：

```
搬运总量只有 **7~12 KB/趟**（81 个 1×1×32 拷贝，每个 64 字节）
就算按 1 GB/s 算也只有 ~12 µs，占 8.461 ms 的 **0.14%**
```

⇒ **搬运通路的代价不是字节量，而是它触发的提交/轮开销** ——
而那个开销**已经在地板里**了（67.4 µs 正是在**搬运提交**上量出来的）。
**模型不需要再加一项。**

**教训**：把「某个量还没进模型」当成待办之前，**先量一下它的量级**。
如果它只占 0.14%，它就不该是一项，而应该是一句话。

## 2. ★ 修正我自己报错的一个数：−9.9% 是**虚高**的

docs/51 §0 我写：「三核（用实测地板 67.4 µs）预测 7.876 ms vs 实测 8.742 ms → **−9.9%**，
方向一致的系统性偏差」。

**那个 8.742 ms 是「只挂 timer 的干净值」，而 7.876 ms 是我用干净地板算的 —— 看似配套，
但我当时把 8.742 和带 dump 的 11.056 混着用过，导致残差的解释（「地板随提交规模上升」）
被夸大了。** 用**一致的干净值**重算：

| 配置 | 预测（FLOOR=67.4） | 实测（干净） | 误差 |
|---|---|---|---|
| cm=7 | 7.876 ms | 8.461 ms | **−6.9%** |
| cm=1 | 14.774 ms | 15.419 ms | **−4.2%** |
| cm=3 | 9.219 ms | 13.501 ms | −31.7%（见 §3） |

⇒ **两个配置都在 7% 以内，不是「系统性低估 10%」。**

⚠️ **工具里还留着一个不一致**：`submit_budget.py predict` 用的实测值是
**带 dump 的**（14.107 / 22.156 ms），而 `budget` 用的是**干净的**。
两个子命令因此给出不同的误差。**这是已知的不一致，已在文档和工具输出里标注** ——
数值结论以**干净值**（`budget`）为准。

## 3. 仍然存在的唯一异类：2 核 −31.7%

cm=3 是唯一预测误差超过 10% 的配置（−31.7%）。这与 docs/45/46/49 记录的现象是同一个：
**2 核的每轮/每提交开销比 3 核高**（零算术量提交：138.0 µs vs 89.0 µs），
而模型用的是**同一个地板常数**。

⇒ 模型的**适用边界**：**同核数内有效（≤7%）；跨核数不成立**（2 核要另标定）。
这不是模型形式错了，是**地板常数随核数变化**这件事还没被建模（docs/45/46 已记录原因：
现有三个配置的自由度不足以把「每提交地板」与「每轮开销」分开）。

## 6. 教训（本轮新增）

1. **★ 把「某量还没进模型」当待办之前，先量它的量级。** 我上一轮把「搬运字节量」列成待办，
   本轮一量只占 **0.14%** —— 它不该是一项，该是一句话。**量级决定它是待办还是脚注。**
2. **★ 报误差时，被减数和减数必须来自同一套测量。** 我把「干净地板」和「带 dump 的实测」
   混着用，报出了虚高的 −9.9%。**误差本身也要做一致性检查。**
3. **★ 模型要写清适用边界。** 「同核数内 ≤7%，跨核数不成立」比「误差 ≤7%」诚实得多，
   而且**指向了下一次该标定什么**（2 核的地板）。
4. **一个数报错了就改，并在正文里写清改了什么。** 本篇 §2 就是。
   **在收官文档里留一个已知错误，比不写收官文档更糟。**
