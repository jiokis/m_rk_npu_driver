## 一、编译器骨架（静态结构）

### 1.1 ★★★ 底座是 **ONNC**（开源，不是自研）

全部 pass 的基类签名都是：

```cpp
onnc::CustomPass<rknn::XxxPass, onnc::ModulePass, void>
```

**⇒ 一次性枚举出全部 67 个 pass（38 个 rknn + 29 个 onnc）。**
（docs/126）

**意义**：编译器不是黑盒 —— 它是「开源骨架 + 私有 pass」，这决定了后续所有观测手段的可行性。

## 三、运行侧结构（动态）

| 结论 | 文档 |
|---|---|
| **IR 表是编译器自己的性能模型**（`Cycles(DDR/NPU/Total)` + `RW(KB)`） | 104 |
| **提交结构**：329 次提交全部服从「3 核 ⇒ `task_number ≡ 0 mod 3`」 | 133 |
| **40 字节 `rknpu_task` 描述符**，`+0x04` = 算子序号 | 135 |
| ★★ **修正：3 次重复不是 3 个核，而是 3 个 surface**（换 core_mask 重抓证明） | 136 |
| **运行侧算子数 = IR 表 NPU 算子数**（9/9 精确） | 137 |
| **`Σtasks = 3P + S`**（P = 算子数） | 134 |
| **负结果**：tensor 地址链**不能**揭示段边界 | 138 |

### 重要的自我修正史

```
135「40 字节 task 的 op_idx 证明 3 次重复就是 3 个核」
  → 136「换 core_mask 重抓 ⇒ 1 核仍是 3 份 ⇒ **是 3 个 surface，不是 3 个核**」
```

**⇒ 这是本项目最典型的一次「样本量为 1 就下结构结论」的翻车与纠正。**

## 七、SD-Turbo 部署中**新挖出的逆向结论**

### 7.1 ★★★★ `fuse_mul_into_sdpa` 的「bug」= **numpy 2.x 不兼容**

工具链内部做 `float(np.array([x]))`（ndim>0 转标量），
**numpy 1.x 只是 `DeprecationWarning`，2.x 变硬错误**。

**⇒ 钉 `numpy==1.26.4` 后规则正常工作**，SDPA 融合生效、模型普遍变小。

**⇒ 通用教训：工具链报「规则 bug」，先查运行时依赖版本。**

### 7.2 ★★★★ 板子的硬限制链

| 限制 | 值 | 现象 |
|---|---|---|
| kernel `cma=` | 出厂 **128M** | `RKNPU: failed to allocate IOVA: -12` |
| 调大后 | 3072M | 单模型能 init |
| **真正的上限** | **IOVA ~3.6 GB（体积，不是个数）** | `up1`(515 MB) 可驻留 7 个、`up3`(70 MB) 可驻留 12 个 |

**⇒ CMA 调大有用，但驻留能力受 IOVA 空间限制。**

### 7.3 ★★★ 加载开销在 **NPU 侧**，不在磁盘

| 来源 | `load_rknn` | `init_runtime` | `release` |
|---|---|---|---|
| eMMC 首次 | **1.68 s**（307 MB/s） | 0.54 | 0.21 |
| eMMC 页缓存 | 0.24 | 0.52 | 0.20 |
| **tmpfs** | 0.23 | 0.35 | 0.20 |

**⇒ 换存储介质无用**（页缓存后一样快）；真正开销是 **`init_runtime` + `release` ≈ 0.6 s**。
**⇒ 按「使用频率」分配常驻**（UNet 6 段常驻、CLIP/VAE 按需）
⇒ **UNet −42%、总计 −31%、NPU 占用 59%→88%、加载占比 26.8%→4.4%**

### 7.4 ★★★★★ 算子类边际成本（本轮最重要的定量结果）

**测法必须用「同构链差分」**（`(t16−t1)/15`）—— 因为每次 `inference()` 有 **~50 ms 级 I/O 开销**，
单算子测量会被它淹没（曾因此得出「MAC 几乎免费」的错误结论）。

| 算子类 | 边际成本（640ch×64×64） | ns/元素 | 相对逐元素 |
|---|---|---|---|
| **`exSDPAttention`** | **490.9 ms** | **187.26** | **550×** |
| `Conv` / `ConvAdd` | 32.9 ms | 12.55 | 37× |
| `exNorm`（GroupNorm） | 17.3 ms | 6.60 | 19× |
| 逐元素（`Mul`/`Add`/`Reshape`…） | 0.88 ms | 0.34 | 1× |

**⇒ 这解释了「编译器 MAC 周期模型乐观 4.7×」**：注意力离峰值 70 倍，而它每层都有。

### 7.5 其它工具链行为（都是实测）

| 行为 | 说明 |
|---|---|
| **`Mul + Relu` 融成一个 `MulRelu`** | 造链时要注意 |
| **纯线性链被折叠成 1 个算子** | `x*1.5*0.8*…` 的 64 层链 ⇒ NPU 算子数 = **1**（`do_constant_folding=False` 也拦不住） |
| **纯 `reshape` 被完全消除** | 独立 reshape 模型 ⇒ NPU 算子数 = **0** |
| **IR 表的 `InputShape` 含权重与 bias** | `Conv (1,640,64,64),(640,640,3,3),(640)`；统计元素数时必须只取第 1 个 |
| **标定集必须 NCHW** | NHWC 会报 `shape ... expect 'nchw' like ...` |
| **模型不存在时 `inference` 返回 `None`、计时读到 0.03 ms** | 假读数的陷阱 |

### 7.6 ★ INT8 在这个负载上**不成立**

| 目标 | 结果 |
|---|---|
| 纯 Conv 链 | ✅ **3.19×**（33.03 → 10.36 ms/Conv） |
| 真实 `unet_up3` | ❌ **仅 1.12×**，精度余弦 **0.9676**（门控 0.99 不达） |
| 真实 `vae512_v2`（占 49%） | ❌ **转换直接失败**：`Unkown op target: 0` |

## 八、成本模型：做到了什么、没做到什么

### 做到了（定性 + 机理）

```
t_part ≈ 50 ms（每次调用 I/O）+ Σ 算子类边际成本
```

* `unet_up3` 用它预测 **2355 ms** vs 实测 **2475 ms** ⇒ **−4.8%**（⚠️ 见下）
* 解释了编译器乐观 4.7× 的成因

### 没做到（定量预测式）

| 尝试 | 结果 |
|---|---|
| MAC 周期 + 提交地板（旧模型） | 4 个模型低估 35~56% |
| 单一 `ns/元素`（逐段真实形状回测） | **0/8 段在 30% 内**，中位 **151.6%** |
| 排除权重/bias 后 | **2/8**，中位 **62.2%** |
| 「常数 + 线性」 | 反解出的常数是**负数** ⇒ 形式不对 |

**根因**：`unet_up3` 的 −4.8% 来自**均摊近似**（把所有算子都当成 2.62 M 元素）；
一旦用真实形状就系统性高估 —— **`per-element` 成本随张量尺寸下降**（`vae512_v2` 张量 33.5 M vs 标定 2.62 M）。

**⇒ 建议放弃解析式，改「分档查表 + 插值」。**
