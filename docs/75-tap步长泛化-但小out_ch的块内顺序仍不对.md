# 75 · tap 步长**泛化成功**（`out_ch × 16`），但小 `out_ch` 的块内顺序仍不对

> 接 [docs/74](74-GAP被编译成7x7池化-探针选错了.md)。本轮造了语义等价的 `probe5`
> （Conv+Relu+Flatten+Gemm，**无任何会被编译器改写语义的算子**），却发现了别的问题。

---

## 1. ★ 成功的部分：tap 步长泛化

docs/68 的公式里「每 tap 步长 = 256」其实**不是常数**，而是 `out_ch × align(in_ch,16)`：

```
probe4   conv out_ch=16 ⇒ 9 taps × 16 × 16 = 2304 = WEIGHT_SIZE0 ✅
probe5   conv out_ch= 2 ⇒ 9 taps ×  2 × 16 =  288 = WEIGHT_SIZE0 ✅
probe5   Gemm out_ch= 2, in=2048 ⇒ 1×1 × 2 × 2048 = 4096 = WEIGHT_SIZE0 ✅
```

**⇒ `WEIGHT_SIZE0 = kh·kw·out_ch·align(in_ch,16)`，三个独立算例全部吻合。**
已写进 `src/sim/rknpu/weights.py`（`tap_stride(out_ch)`）。

---

## 2. ⚠️ 没成功的部分：`out_ch=2` 时块内顺序对不上

用两个已知锚点（`W[0,0,0,0]=1.0`、`W[1,1,1,1]=-1.0`）解出 scale 后，按 docs/68 的顺序
（`tap*32 + oc*16 + ic`）重建，**最大误差 1.40**，远超量化容差（scale/2 ≈ 0.004）。

试了 5 种候选块内顺序：

```
A  tap*32 + oc*16 + ic    scale=0.005351  最大误差 0.3204  均值 0.1300   ← 最好但仍不对
B  tap*32 + ic*2  + oc    scale=0.002994  最大误差 0.9461  均值 0.2308
C  tap*32 + oc*2  + ic    scale=0.004090  最大误差 0.9264  均值 0.1927
D  tap*32 + ic*16 + oc    scale=0.004118  最大误差 0.7550  均值 0.2017
E  tap*16 + oc*8  + ic    scale=0.003759  最大误差 0.9323  均值 0.2271
```

**A（probe4 导出的顺序）仍然最好，但误差 0.32 在幅值 ~0.3~1.0 的权重上是 30~100% ⇒ 仍然错。**

**⇒ `out_ch` 变小时，块内结构还有我没建模的东西。**
（候选：docs/44 提过 `out_ch` 可能对齐到 32；probe5 的 `kernels=2` 是否被补到某个宽度、
或 `ic` 的对齐宽度随 `out_ch` 变化 —— 都需要专门探针。）

## 3. 结论与下一步

| 项 | 状态 |
|---|---|
| tap 步长公式 | ✅ 泛化完成（`out_ch × 16`，3 个算例） |
| 块内顺序（`out_ch=16`） | ✅ docs/68 已验证 |
| 块内顺序（`out_ch=2`） | ❌ **本轮发现不适用** |
| 激活量化 | ⬜ 仍待验证（需要一个顺序确定的探针） |

**⇒ 下一步：造一个 `out_ch=16` 的语义等价探针**（复用 probe5 的结构，但把 conv 的

这样可以把「布局」和「量化」两个变量分开。

## 4. 教训（本轮新增）

1. **★ 一个公式在某个参数点上验证过，不等于它在参数空间里普遍成立。**
   `256` 在 `out_ch=16` 时是对的，于是我把它写成了常数；`out_ch=2` 立刻推翻。
   **写公式时要把「哪些量是参数」写进去，而不是把当次观测值写死。**
2. **★ 「最好的候选仍然错」说明候选集不完备，而不是「再调调就行」。**
   A 的误差 0.32 比其他候选小一个量级，但**它仍然远超容差** ⇒
   正确做法是**换探针**（把 `out_ch` 固定在已验证的情形），而不是继续在候选里挑。
   **当所有候选都不合格时，问题在假设空间，不在参数。**
3. **★ 探针要一次只改一个变量。** probe5 我同时改了「去掉 GAP」和「把 out_ch 从 16 降到 2」，
   于是「对不上」无法归因到哪一个。**又是这个错误（docs/66 也犯过）。**
