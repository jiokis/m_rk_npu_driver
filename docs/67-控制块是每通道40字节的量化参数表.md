## 0. 结论

**那个 4096 B 的「控制块」是一张每通道 40 字节的量化参数表。**

```
周期 40 字节（自相关最强：40，强度 236；80/120/160 依次递减 —— 典型的周期信号）
前 4 条记录（probe4，16 个输出通道）：
  记录0 @  0: [4]=1  [8]=29 [13]=3 [16,17]=255,255 [18]=1 [24]=126 [32,33]=128,172 [34,35]=255,255
  记录1 @ 40: [4]=2  [8]=29 [13]=3 [16,17]=255,255 [18]=1 [24]=126 [32,33]=192,176 [34,35]=255,255
  记录2 @ 80: [4]=3  [8]=29 [13]=3 [16,17]=255,255 [18]=1 [24]=126 [33,34]=181,255,255
  记录3 @120: [4]=4  [8]=29 [13]=3 [16,17]=255,255 [18]=1 [24]=126 [32,33]=64,185  [34,35]=255,255
```

### 判读

| 偏移 | 观察 | 判读 |
|---|---|---|
| **+4** | **1, 2, 3, 4 … 递增** | ★ **通道号** —— 这一条就把「记录边界」钉死了 |
| +8, +13, +18 | 恒为 29 / 3 / 1 | 该算子的公共参数（类型/模式之类） |
| +24 | 恒为 126 | 常数（可能是某个默认 scale 或标志） |
| **+32..33** | **随通道变化**（128,172 / 192,176 / 64,185） | ★ **per-channel scale（2 字节）** |
| +34..35 | 恒为 255,255 | int16 的 −1（可能是 shift / 指数，或「未使用」标记） |

**⇒ 量化参数不需要从权重字节里反推 —— 它有一张结构清晰的表。**

## 1. 为什么这一步比继续做探针更值

我上一轮结尾的判断是：「与其继续猜权重布局，不如直接从寄存器/控制块读量化参数」。
本轮验证了这个判断：

| 路线 | 本轮的代价 | 结果 |
|---|---|---|
| 继续做权重探针 | 前 4 轮（docs/62~66） | 拿到「计数级事实」+ 否掉几个假设，**排列仍未定** |
| **读控制块** | **1 轮** | **拿到完整的 per-channel 参数表结构** |

**⇒ 当「猜数据布局」卡住时，去找「产生这个布局的参数表」往往更快。**
参数的**语义**比数据的**排列**更容易读出结构（因为参数表通常规整、周期性强）。

## 2. 这条线索直接连上 docs/62 的悬案

docs/66 留下一个矛盾：**同一个浮点 0.0 在 probe3 编码成 128、在 probe4 编码成 0**。
我当时的推断是「一定有第三个变量，最可能是 per-channel scale」。

**本轮找到了那个变量的存放位置**：`+32..33` 的 per-channel scale。
⇒ 那个矛盾现在变成**可计算**的：把两个探针各自的 per-channel scale 代进
`q = round(w/scale) + zp`，看能否同时解释 128 与 0。

**这正是从「猜」到「验证」的转变。**

**#2 最有判别力**：如果 scale 能同时解释两个探针，量化公式就定了，
**执行器的数值部分就只剩「排列」一个问题**。

## 4. 顺带拿到的：`CVT_CON` 寄存器是「per-tensor」的那一套

probe4 的 `CVT_CON1..4` 全是 `0x00010000`（高 16 = 1，低 16 = 0）⇒ **scale=1、offset=0**，
即**旁路/直通**；`CVT_CON0 = 0x0b`（模式位）；`CVT_CON5 = 0`；`PAD_CON1 = 0xffff8080`。

**⇒ 寄存器里那套是「per-tensor 的粗略参数」，真正的 per-channel 表在控制块里。**
这与 docs/17 记的「`CVT_CON1 = 0x4000ff80`」不同 —— 那是另一个模型的取值，
说明 `CVT_CON*` 的内容随算子类型变。

## 6. 教训（本轮新增）

1. **★ 猜「数据布局」卡住时，去找「产生布局的参数表」。**
   我在权重字节上花了 4 轮（docs/62~66），而控制块一轮就给出了完整结构。
   **参数的排列通常比数据的排列规整得多** —— 因为它是程序生成的，不是算出来的。
2. **★ 自相关是找周期结构的最省力工具。** 我用「非零位置」看不出规律，
   一次自相关就直接给出周期 40（且 80/120/160 递减，确认是真周期而非巧合）。
   **有重复结构的数据，先做自相关。**
3. **★ 「通道号在表里递增」是定位记录边界的最强线索。** 偏移 +4 是 1,2,3,4…
   这一条同时确认了「记录大小 = 40」和「表从偏移 0 开始」，不需要别的假设。
   **找这种「自带索引」的字段。**
4. **★ 我上一轮的判断被验证了：换入口比硬推更快。** 上一轮结尾我提出「去读参数表」，
   本轮一次成功。**在一条线上连卡两轮之后，应该主动换入口，而不是加大力度。**
