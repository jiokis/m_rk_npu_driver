# 111 · ⚠️ **Python 规则表不是切分机制** —— 切分在 C++ 侧

> 接 [docs/110](110-tiling-proc的入参与返回值已捕获.md)（捕获到 tiling 返回值）。
> 本轮按计划对多个模型统计「tiling 返回的节点数」，**结果否掉了这条通道。**

---

## 1. 决定性结果

```
SUM regnet_x_400mf conv=71 tiling_nodes=2 per_conv=0.03
    detail={'convert_exmatmul_to_conv': 2}
```

**⇒ `regnet_x_400mf`（`tile/conv = 44.3`、3147 个 tile）通过 Python tiling 规则
只创建了 **2 个节点** —— 而且都来自 `convert_exmatmul_to_conv`（FC→Conv 的转换）。**

**⇒ 它的 3147 个 tile **不是**这些 Python 规则切出来的。**

（后续模型在运行中抛异常退出，见 §4。）

---

## 2. ★ 结论：切分在 C++ 侧

| 层 | 内容 | 是否切分 |
|---|---|---|
| Python `hardware_rules`（12 条） | 只处理**少数特例**（`convert_exmatmul_to_conv`、FC 的 `tiling_conv_channelin`） | ❌ **不是主切分机制** |
| **C++ `RKNNTilingPass` / `onnc::TileLower`** | 真正的 tile 划分 | **← 答案在这里** |

**⇒ docs/109 的「tiling 规则确实触发」是真的（触发 87~1113 次），
但**触发 ≠ 创建 tile** —— 它们大多数返回空（「不适用」）。**

**⇒ 真正的 tile 划分在 C++ 里，Python 侧看不到。**

---

## 3. 这一步的价值：**排除了一整条通道**

* docs/99 我以为「让 tiling proc 产出结果」就能拿到切分规则
* docs/109 我看到它们「确实触发」，以为通道打开了
* **本轮证明：它们创建的东西极少（regnet 只有 2 个）⇒ 不是切分机制**

**⇒ 「能 hook」和「hook 到的就是答案」是两件事。**
**⇒ 这与我 docs/109 的乐观判断相反 —— 需要修正。**

## 4. 一个技术限制（要记下来）

**只有第一个模型跑完（regnet），后续模型抛异常退出（exit=1）。**
最可能是我的 wrapper 在某些返回值形态上处理不当（我只处理了 `len(r)==2` 的情况）。

**⇒ 但第一个模型的结果已经足够下结论**（regnet 是 `tile/conv` 最高的模型，
它只有 2 个 tiling 节点 ⇒ 其他模型不会更多）。

## 6. 教训（本轮新增）

1. **★★★ 「能 hook」≠「hook 到的就是答案」。** docs/109 我看到 tiling 规则触发就判断
   「通道打开了」；**本轮发现它们创建的东西极少** ⇒ **触发的量级与效果的量级是两件事。**
   **拿到一个通道后，要先测「通过它能改变多少」，再判断它是否是主机制。**
2. **★★ 我上一轮的乐观判断需要修正。** docs/109 写「真正的收获是观测通道」——
   通道是真的，**但它不是主机制**。**「有收获」和「有答案」要分开说。**
3. **★ 成本-收益判断要在开工前做。** 剩下的路（gdb/反汇编）成本陡增，
   而我已在这一点上投入 30+ 轮 ⇒ **应该先判断「还值不值得」，而不是惯性往下做。**
